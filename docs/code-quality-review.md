# 代码质量：当前风险与维护顺序

本文只记录当前实现的风险和验收边界，不保留逐轮审阅报告。当前行为见
[`architecture.md`](architecture.md) 与 [`mod-internals.md`](mod-internals.md)，验收数字见
[`reliability-repairs.md`](reliability-repairs.md)。

## 已收敛的结构问题

- Python 连接、命令、门面和 CLI 已按职责分层；live 自检入口、默认套件、共享运行时与领域检查
  已分离，旧 CLI 和检查名保持兼容。
- `InputSession`、`MacroSession` 以及封包、传送、飞行、legacy 录制请求各有唯一状态所有者，
  不再用可变别名或跨 TU reset 清单复制生命周期。
- 常规 tick 查询和事件使用定长快照/队列、局部异常边界及后台格式化。危险 SDK 读取应继续
  收进局部边界，不能用整个持锁 tick 的 SEH 代替。
- 实体、ECS、飞行、传送和封包注入使用分阶段请求与编号/代次隔离；实体攻击、飞行和其他服务端
  领域统一 UUID+epoch 解析，不做隐式玩家名兜底。
- 违规/断线页、入站和发送探针按所有权分 TU；发送历史使用原子环，导出只读取完整发布记录。
- PacketTap 常规身份采集不序列化；显式 `serialize_ids` 有默认 1 秒累计预算，超预算停止后续
  重序列化并记录 `Budget`/`serialize_skipped`。
- 四个常驻 hook 已移出 DLL 静态构造/析构，受控空闲真实重载已通过；已有世界的
  `/togglefly` 会重新注册，验收包含能力变化与恢复。

这些结论不表示整个 tick 已隔离、所有 SDK 调用零分配，或性能一定提升。

## 未决风险

| 优先级 | 风险 | 当前证据与处理边界 |
| --- | --- | --- |
| 高 | 任意在途 tick 回调的卸载排空未证明 | `lifecycle_prepare` 只检查自有工作及输入生命周期快照；不能把它当成整个游戏线程已静默 |
| 高 | 其他游戏读取并非全部有局部异常边界 | pre/post 客户端读取和主要采集路径已覆盖；新增 SDK 调用仍需逐个审查，不能推广为整个 tick 安全 |
| 中 | HBUI 异常退档的形成根因未闭合 | 已有 leave_id、菜单快照和正常恢复验收；不得放宽保存/进入门禁来掩盖 `worlds.ready=false` |
| 中 | 显式诊断可能改变时序 | `serialize_ids` 在原上下文同步重序列化并可能分配；预算不能中断正在执行的 SDK 调用。`mem_arg`、守望和发送探针同属默认关闭诊断 |
| 中 | 高频查询后的管道失联仍有历史边界 | 不添加未经验证的跨线程 `CloseHandle` 看门狗；分批查询、显式关闭客户端，卡住时受控重启 |
| 外部 | 游戏共享序列化缓冲存在跨线程竞态 | 可产生粘连帧并触发 BadPacket；harness 不补丁游戏网络栈，只减少不必要的并发状态同步并保留取证 |

## 维护顺序

1. 新崩溃/丢数据风险优先于结构和性能；先保存首错与现场，不覆盖原始异常。
2. 生命周期改动必须验证拒绝路径、唯一终结、旧代次隔离和恢复，不只验证 happy path。
3. 性能结论需要同 DLL、同场景的受控对照；native 零分配/并发模型不能替代真实游戏时序。
4. 文档只更新当前状态和未决范围；旧审阅过程查 Git 历史，不在此文件继续追加。
