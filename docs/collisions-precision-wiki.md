# 方块碰撞解算、卡墙挤出与实体推挤是怎么工作的？（`1.26.51.01` 实测与机制解析）

跑酷圈里关于基岩版碰撞箱一直有几句半真半假的话：「跨大坐标碰撞箱会缩水」「卡在墙里会被 `0.1` 推出去」「连跳能刷碰撞箱」「实体挤来挤去有公式」。本文用逐 tick 实机数据 + 反编译把这几件事一次讲清。

> **文档分工**：本文面向玩法理解与跑酷设计，略去反编译地址与组件编号；完整证据链、逐条指令与逐 tick 原始数据见 [`notes/collisions-precision-12651.md`](notes/collisions-precision-12651.md)。

## 一、一分钟结论速查

| 说法 | `1.26.51.01` 的真实情况 |
| --- | --- |
| 「高坐标碰撞箱会缩涨」 | **真，且有两种途径**：①传送/换姿态“重建”那一刻，宽度被对齐到坐标精度网格（`x=16384` 处 `0.6015625`、`x=131072` 处 `0.59375`、`x=1048576` 处只剩 **`0.5`**）；②**走路跨过 `2^n` 边界**（如 `x=1048576`）时宽度逐拍跳变——实测在 `0.375~0.875` 之间摆动，往返走完一度停在 **`0.375`**。只有**不跨边界**的走路宽度才一位不变 |
| 「卡墙会被 `0.1` 加速度挤出」 | **真，但有条件**：只推水平方向、推力模长恰好 `0.1` 格/拍、方向是“离最近的空隙”、且空隙必须在 `±1` 格内。被完全封死在石腔里时**纹丝不动**（实测 97 拍零位移） |
| 「连跳会改垂直碰撞箱」 | **在 `2^n` 高度边界上是真的**：站在 `y=127`（身体跨骑 `y=128` 精度边界）连续跳 15 次，落地高度**每跳精确放大一格精度（+`0.0000305`，共 +`0.00044`）**；站在 `y=63`（跨 `y=64`）则一位不变。不跨边界的连跳（原点 12 次、`y=101` 站 120 拍高度 `1.8000031`）确实不会变 |
| 「实体之间有推挤公式」 | **真**：按 `d_raw = max(\|dx\|,\|dz\|)` 检查 `[最小距离, 最大距离]`，命中后取 `s = sqrt(d_raw)` 按 `min(1, 1/s) × 强度 × 推力倍率` 把推力写进双方的“待执行位移”；实测两只重叠的牛几拍内弹开（峰值约每拍 `0.6` 格）。**但本地玩家免疫**：生存/创造模式下玩家 `mPosDelta` 全程为零，牛反而会自己从玩家身上“弹开” |

## 二、方块碰撞是怎么解出来的

每拍移动分三步走，顺序固定是 **先竖直、再 X、再 Z**（不是 Java 那种按 `\|dx\|>\|dz\|` 换轴的算法）：

1. **收集**：把附近的方块碰撞盒抓成一张表；
2. **逐轴裁剪**：把这一拍想走的距离拆成「竖直 / X / Z」三个独立小步。每个小步对表里**每个**方块盒（从后往前）做一次判定：
   - 如果**还没碰到**这个方块：做“运动裁剪”——这一步会不会越过它的面？会就把步长缩到刚好贴面（**不留一点缝**，直接对齐方块面）；
   - 如果**已经陷进去**了：做“最小推出”——三个轴里哪根轴的“陷得最浅”就往哪边推出去（同深度时优先 X，再 Y，再 Z）；
3. **写回**：解完的盒子**直接在旧盒子上加移动量**（增量平移），位置坐标反而是从盒子中心“抄”出来的。

对跑酷的实际意义：

- **贴墙滑行时你的碰撞箱面是精确对齐方块面的**，没有隐藏 epsilon，落缝判定就是纯的 `f32` 精度问题；
- **先 Y 后 XZ** 意味着下落与水平移动在同拍内的先后关系是固定的：落地拍的水平位移用“已经贴地面”的盒子算，这是很多 Blip/落缝技巧成立的基础。

## 三、精度：什么时候会缩、什么时候不变

### 3.1 重建量化（传送/换姿态那一刻）

碰撞箱在重建时被坐标精度网格“切”：传送、出生点重定位、潜行/爬行换姿态、被碰撞面单边夹住。重建后：

| 玩家中心 x | 网格精度（ULP） | 实测碰撞箱宽度 | 与理论 `0.6` 的差 |
| --- | --- | --- | --- |
| 242 | `0.0000153` | `0.6000061` | `+0.0000061` |
| 1024 | `0.000122` | `0.6000977` | `+0.0000977` |
| 16384 | `0.001953` | `0.6015625` | `+0.0015625` |
| 131072 | `0.015625` | `0.59375` | **`−0.00625`** |
| 1048576 | `0.125` | **`0.5`** | **`−0.1`** |

在 `x=1048576` 这种量级，`0.6` 在 `f32` 里**根本不可表示**（只能取 `0.125` 的整数倍），所以宽度必然缩到 `0.5` 或涨到 `0.625`。方向可涨可缩：取决于 `x±0.3` 各自往哪边舍入。

### 3.2 走路：不跨边界一位不变，跨边界逐拍漂移

每拍移动是在旧盒子上“加”。**盒子的两端处在同一个精度区间（binade）内时**，两侧的舍入永远同步（`round(k+δ) = k+round(δ)`），宽度一位不变——原点区走路 31 拍实测宽度变化全为 0。

但**当盒子跨骑 `2^n` 边界**（比如盒子 `[1023.5, 1024.1]`：最小值在 `1024` 以下用细网格、最大值在以上用粗网格）时，两侧**各自舍入、不再同步**：

- `x=1024` 边界往返走：宽度在 `0.5999756 / 0.6000366 / 0.6000977` 之间跳了 8 次（每跳 ±`0.000061`）；
- `x=16384` 边界：4 次跳变（±`0.00098`）；
- `x=1048576` 边界：**宽度在 `0.375~0.875` 的 8 个值之间大幅摆动**（跨界段每拍 ±`0.0625`），往返走完一度停在 **`0.375`**——比理论 `0.6` 窄了 `0.225`！

跳跃同理：站在 `y=127`（身体跨骑 `y=128` 边界）连续跳 15 次，落地高度**每跳精确放大一格精度**（`1.8000183 → 1.8004456`，每跳 `+0.0000305`，无一回退）——这就是社区说的「特定 Y 高度连跳改碰撞箱」，实测为真。而站在 `y=63`（跨 `y=64`）跳 15 次高度一位不变（该往返恰好恒等），原点连跳 12 次同样不变。天花板对照：头被 `y=65` 的天花板夹住时是**整个盒子被推下来**（脚也跟着降），高度不变。

### 3.3 对跑酷的设计含义

- **高坐标做窄缝/落缝要按“缩水后的宽度”重新核对**：`2^20` 附近重建后是 `0.5` 宽，跨界走几步还可能变成 `0.375`——有些 Java 行得通的贴缝走法在基岩高坐标反而更容易进缝，也更容易“意外掉进看起来不可能掉进的洞”；
- **想刷窄/宽碰撞箱**：跨 `2^n` 边界行走刷宽度、站 `y=127/128` 这类边界刷高度，都是可复现路径；传送重建则一次性定量；
- **刷高度有方向性**：`y=127` 的连跳是单调放大（每跳 +`0.0000305`，无一回退），刷多少跳涨多少。

## 四、卡墙挤出：`0.1` 的真实形态

### 4.1 什么时候会被挤

系统每拍检查两件事：这个实体**当前和方块重叠**（本拍解算深度 ≥ 1e-6 格）、它**挂了“向最近空隙推”的能力位**（普通生物和玩家出生就有）。两者同时成立时才挂“本拍要推挤”标志。

### 4.2 推多少、往哪推

- **方向**：把 `±1` 格范围内的方块盒质心和你的中心一比，**只取水平分量**（X/Z），归一化后乘 `0.1`。质心比不出来（四周均匀）时改试“上下左右挪一格还有没有空位”；
- **写入方式**：不是直接传送，而是写进“待执行位移”——所以走路的大步幅不会被覆盖（只有你当前的待执行位移比 `0.1` 小才写），落地重力也不受它影响；
- **推力模长实测恰好 `0.10000000`**（对角挤压时每轴 `0.1/√2 = 0.0707`），落地后按地面摩擦 `×0.546` 逐拍衰减；
- **竖直方向永不推**：被顶进天花板不会因此下推，往上顶进方块也不会被垂直挤出。

### 4.3 关键限制：±1 格之外就是死

把玩家整个封进 `5×3×5` 的石腔（每个方向要穿 `1.8~2.8` 格才出去）：系统在 `±1` 格步长内找不到任何空位 → 方向直接清零 → **玩家被冻在石头里**（实测 97 拍位置一个比特都不变）。所以：

- **单层墙/薄地板**：几拍内被挤出来，方向是“最近的面”；
- **完全封闭**：不挤、不动（等待挖掘/指令救援）；
- 防卡墙建筑（如基岩层保护脚下的陷阱房）**至少留一个 `±1` 格内的水平出口**，否则玩家会真·卡死。

### 4.4 容易混淆的邻居

- **活塞/掉落沙推人**走的是另一套（`PushableByBlock`，按运动方向逐轴算），和 `0.1` 挤出无关；
- **上台阶/自动步高**（0.5625 等）是独立系统，见正主文档。

## 五、实体推挤：谁推谁、推多少

推挤的完整公式（`PushMode::Default`，绝大多数实体用这条）：

```
d_raw = max(|dx|, |dz|)            # 水平两轴差值的较大者（用于距离门判断）
若 d_raw < 最小距离（含完全同心）→ 不推
若 d_raw − 自身半宽 > 最大距离 → 不推
s = sqrt(d_raw)
推力 = min(1, 1/s) × 强度 × (1 − 对方“穿透系数”) × 推力倍率
方向 = 双方连线方向，分别乘 mPushScaleOther（推对方）与 mPushScaleSelf（推自己）
写入位置 = 双方各自的“待执行位移”（与卡墙 0.1 挤出同一通道）
```

- **谁有资格推**：只有**服务端在做 movement tick 的实体**（普通生物等）执行推挤；完全同心（dx=0）直接被最小距离短路——**贴得越近反而越早停推**；
- **本地玩家免疫**：生存/创造模式下玩家作为“被推方”时推力不落地（实测 dx=0.15 静止重叠 40 拍、行走穿越，玩家 `mPosDelta` 全程为零）；**但牛会自己从玩家身上弹开**（静止重叠时牛被推离约 `1.0~1.26` 格直至分离，生存/创造无差异）；
- **两只牛叠在一起**：几拍内弹开（实测首拍峰值约每牛 `0.6` 格），分开到最大距离之外就停；
- **行走穿越**：移动的玩家从牛身上走过时牛不动（与静止重叠不同，瞬时重叠不触发——机制细节见正主文档的边界表）；
- **骑乘双方**（船/矿车/坐骑）静态上直接短路不互推；船/矿车自身的被推走它们各自的专用物理路径。

## 六、常见问答

**Q：在 `x=100 万` 的坐标做跑酷，哪些判定会变？**
A：碰撞箱宽度重建后变 `0.5`，**走路跨过 `x=1048576` 时宽度还会在 `0.375~0.875` 之间跳**；方块面贴合按 `0.125/0.0625` 混合网格对齐。速度、重力递推本身不变。

**Q：卡墙挤出能不能当加速器用？**
A：每拍模长恰好 `0.1`，且只在重叠时触发、方向由几何决定，走出墙体即停——不能叠加成持续加速。

**Q：想刷一个“窄碰撞箱”过缝？**
A：三条可复现路径：①传送到高坐标重建（一次性定量化）；②**跨 `x=2^n` 边界来回走**（宽度逐拍跳变，`2^20` 处实测能走到 `0.375`）；③站 `y=127` 连跳刷高度（每跳 +`0.0000305`，单调放大）。

**Q：两只牛叠着分不开？**
A：给它们一点距离（别完全同心——同心会被最小距离短路），几拍内自己弹开；但它们**不会把你弹开**——被推的永远是自己会动的那一方，你的碰撞箱和位移纹丝不动。

**Q：连跳刷高度在哪最划算？**
A：目前实测只有 `y=128` 这类大边界（`min.y` 细网格、`max.y` 粗网格）有效且单调；`y=64` 边界恰好恒等、原点不变。刷高度前先确认自己的身体跨在哪条精度边界上。
