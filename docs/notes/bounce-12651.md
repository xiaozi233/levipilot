# 黏液块反弹与「上层覆盖方块」判据（1.26.51.01）

> 版本：`1.26.51.01`（LeviLamina 26.51.7），RVA 以映像基址 `0x140000000` 计。
> 目标问题：黏液块上覆盖方块时，什么条件下还能反弹；为什么 0.375 格高的雪层
> 「有时弹、有时不弹」。
> 账本：`skills/bedrock-re/findings/1.26.51.01/cases/slime-bounce-coverage/`。

## 0. 结论速览

- 判据是**形状中心 vs 探针**：解析器把实体 AABB 的 `minY` 减 `0.2` 当探针，
  在候选形状里取「中心 Y 不高于探针」的最高者；选中的方块决定 restitution。
- 覆盖块顶面在黏液上表面、高度 `h` 时，其碰撞盒中心在 `top − h/2`。探针在
  落地瞬间等于 `top − 0.2`，所以：**`h ≥ 0.4` 时覆盖块被选中（不弹），
  `h < 0.4` 时覆盖块被跳过、退回黏液（弹）**。
- 实测：1 层(0.125) 在 0.25–12 的 1/16 网格上恒弹；4 层(0.5) 及以上恒不弹；
  **3 层(0.375) 是唯一的临界高度**——雪层中心只比探针高 0.0125，结果取决于
  该次落地的候选表里还有没有黏液块，因此随落差翻转（同一落差可复现，不是随机）。
  2 层也有同源的窄缝（1/16 宽），只是比 3 层稀（§7 的预测器给出全部位置）。
- 候选表（`MoveRequest+0x58`）的填充判据已闭合：**收集盒下界 < 黏液顶就有黏液块**，
  而 `收集盒下界 = min(preY − 0.5625×1.01, preY + δy − 0.2)`（§3.2–§3.4，
  75 个按 tick 对齐的样本 0 反例）。
- 旧说法「6/16=0.375 一定弹」不成立；「中心判据 + 0.4 阈值」的数学成立。

## 1. 落地处理器与解析器

| 角色 | 地址（VA） | 作用 |
| --- | --- | --- |
| `@bounce_handler` | `0x148B5DB00` | 落地判定 + 取 restitution + 写 `ApplyRestitution` |
| `@block_pos_resolver` | `0x141E144A0` | 位置 → (方块坐标, 方块指针) |
| `@bounce_threshold_f32` | `0x14EA350B0` | `0.080000117f`（\|vy\| 门槛） |

处理器结构（与 45.01 的 `sub_146378200` 同构，只有地址变化）：

```c
if ((*flag & 2) == 0) {                       // 本 tick 没有需要跳过的标志
  vy = state_vector.vel.y;                    // [r8+0x1C]
  if (vy < 0 && fabsf(vy) >= 0.080000117f) {
    aabb_copy = *aabb;                        // 24 B，来自 AABBShapeComponent
    resolver(container, &out, &aabb_copy);    // container = MoveRequest + 0x58
    if (out.block) {
      coef = out.block->vtable[0x3E8](out.block, arg, &out.pos);   // 方块 restitution
      if (fabsf(coef) > 1.1920929e-7f) {
        entry = getComponent(0x7DF54114, entity);                 // ApplyRestitutionComponent
        cur   = entry->y;
        if (coef == -1.0f && cur > 0) { ... }                     // 蜂蜜块粘性分支
        else entry->y = fmaxf(coef * -vy, cur);
      }
    }
  }
}
```

解析器（`0x141E144A0`）的关键几行：

```c
v = aabb[1] + -0.2f;      // 探针 = minY - 0.2
aabb[1] = v; aabb[4] = v; // 查询盒 Y 压成一个点（X/Z 仍用盒中心）
for (shape in shapes) {              // 24 B/个，世界空间 AABB
  cy = (shape.maxY - shape.minY) * 0.5f + shape.minY;
  d  = v - cy;
  if (d < 0) continue;               // 中心高于探针 → 跳过
  if (d < best_d) { best = shape; best_d = d; }        // 取最高中心
  else if (d == best_d) { 水平中心更近者优先 }
}
if (best) { pos = floor(shape.min); block = refs[best_index]; }
```

实测候选表布局（客户端与服务端各一份，地址不同、内容同构）：

- 黏液块：`y = [−60, −59]`，中心 `−59.5`
- 3 层雪：`y = [−59, −58.625]`，中心 `−58.8125`
- 探针：`−58.825`（AABB `minY = −58.625`）→ 雪层被跳过，黏液被选中。

## 2. 实测矩阵

场地：3×3 黏液（y=−60）+ 3×3 石基座（y=−61），中心正落，`record` 逐 tick。
判据：落地后 `max(vy) > 0.02` 记为弹。

| 覆盖 | 高度 | 落差 0.25–6.0 格 |
| --- | --- | --- |
| 无 | 0 | 全弹 |
| 雪 1 层 | 0.125 | 全弹（1/16 网格 0.25–12 无缝隙） |
| 雪 2 层 | 0.25 | 基本全弹，但有 8 个 1/16 宽的窄缝（§7） |
| 雪 3 层 | 0.375 | **翻转**见下 |
| 雪 4–5 层 | 0.5 / 0.625 | 全不弹 |

3 层（0.375）逐档（落差 → 结果）：

```text
0.25  弹   0.75  不弹   1.25  弹   1.75  弹   2.25  弹   2.75  弹
0.375 弹   0.875 弹     1.375 弹   1.875 弹   2.375 弹   2.875 弹
0.5   弹   1.0   不弹   1.5   不弹   2.0   不弹   2.5   弹     3.0   弹
0.625 弹   1.125 不弹                              2.625 不弹   3.0+  弹
```

同一落差重复 2–3 次结果一致；水平落点偏移 0–0.29、覆盖宽度 1/3/5 格都不改变结果
（说明不是「踩在边上」的问题，只由竖直方向的落地相位决定）。

## 3. 为什么 0.375 会翻转

三段链条，三段都已闭合：

1. **候选表**（`MoveRequest+0x58`）= 本 tick「收集盒」碰到的方块碰撞形状，由
   `sub_1431C2F50` 填充（§3.2）；
2. **解析器**用移动后 AABB 的 `minY − 0.2` 当探针，跳过中心高于探针的形状，取最高的（§1）；
3. 选中方块的 restitution 决定弹否（§1）。

0.375 的 3 层雪中心 `−58.8125` 恒高于探针 `−58.825`（差 0.0125），**永远被跳过**，
于是结果完全押在「候选表里有没有黏液块」。这一条以前只能靠扫描，现在有了填充判据。

### 3.1 宿主与内存布局

候选表是 `MoveRequestComponent` 的成员（id `0x4C8F7288`，152 B；视图构造
`0x148B6AB80`：StateVector(36)/AABBShape(32)/MoveRequest(152)/ActorDataFlag(24)/
VerticalCollisionFlag）。在 resolver 入口按 `rcx − 0x58` 抓 128 B（`hook_install
mem_arg=0 mem_offset=-88 mem_size=128`）实测布局：

| 偏移 | 内容 |
| --- | --- |
| +0x00..+0x14 | 移动前 AABB（脚部 minY、身高 1.8） |
| +0x18..+0x2C | **收集盒**（§3.2 的并集盒；解析器不读它，它是填充的缓存键） |
| +0x30..+0x38 | 本 tick 的**请求位移**（竖直分量 = 含重力/阻力的 vy） |
| +0x3C..+0x44 | 填充读的那份位移；**移动后会被改写成实际应用的（裁剪过的）位移** |
| +0x48..+0x50 | 0.01, 0.01, 0.01 |
| +0x58 / +0x70 | 候选形状数组（24 B/个）/ 方块指针数组（8 B/个） |

⚠️ +0x30 与 +0x3C 两处位移在填充时刻相同，移动之后 +0x3C 变成裁剪值。**抓表时若用
+0x3C 反推盒，会得到偏低的下界**——本轮第一版就栽在这里（25 个样本里 6 个假矛盾）。

### 3.2 填充代码（本轮闭合）

链路：每实体系统体 `sub_1431DD080`（视图 = `{0xAF9E0C56, AABBShape, 0x9AB0D3FF,
MoveRequest}`，后两个 id 未解析出名字）→ `sub_1431C2F50`（1800+ 行，含去重/合并）。
`sub_1431C2F50` 里与本题有关的三段：

| 地址 | 作用 |
| --- | --- |
| `0x1431C3049`..`0x1431C3122` | 用 `preAABB(a2)` 与请求位移做**扫掠盒**（逐轴按符号单向外扩，长度先夹到 16） |
| `0x14B177650`（调用点 `0x1431C314A`） | **台阶盒**：`*a3 * 1.01` ⇒ 下扩 `autoStep×1.01`≈0.5681、上扩 `autoStep`≈0.5625 |
| `0x149026EB0`（调用点 `0x1431C3193`） | 另一个从 (位移, autoStep, preAABB) 生成的候选盒 |
| `0x1431C31F7` | 下界再取 `a2.minY − 0.2 − fabs(delta.y)` |
| `0x1431C31FC` | 上界再取 `a2.maxY + 0.08` |
| `0x1431C324A`..`0x1431C32B0` | 若新盒被 `+0x18` 的旧盒**包含**就 `return`：不重建、不改表（缓存是粘的） |
| `0x1431C34D9` | 重建路径：`a10->vfn[+0xB0](out, &box, 1, …)` —— 按盒向方块源要碰撞形状 |
| `0x1431C34DF` / `0x1431C35FA` | 把结果写回 `MR+0x58`（`add [r13+0x60], 0x18` 就是 24 B `push_back`） |

把上面三处取 min/max 合起来，**收集盒**是：

```text
bottom = min( preY + δy ,        // 扫掠盒
              preY − 0.5625×1.01, // 台阶盒下扩
              preY − 0.2 − |δy| ) // 预测项
top    = preY + height + 0.5625   // 台阶盒上扩（+0.08 的项被它盖住）
X/Z    = preAABB 的 X/Z（水平不扩）
```

因为 `δy < 0` 时 `preY + δy − 0.2 < preY + δy`，扫掠项永远被预测项盖住，所以

```text
bottom = min( preY − 0.5681 , preY + δy − 0.2 )      (δy<0)
```

`preY` = 移动前 AABB 的 `minY`，`δy` = **请求**位移的竖直分量。

### 3.4 判据的最终形态

3 层雪（覆盖块中心恒被跳过）时：

```text
弹  ⇔  黏液块在候选表里
    ⇔  收集盒下界 < 黏液顶
    ⇔  min(preY − 0.5681, preY + δy − 0.2) < 黏液顶
```

`preY` 与 `δy` 都是**该 tick 的运行时状态**（取决于落速与落地相位），所以「哪些落差弹」
不是一条关于落差的曲线，而是一条关于相位的不等式。落差只通过 `(preY, δy)` 间接决定它。

顺带解释另外两档（覆盖高度 h，脚部落在覆盖块顶、探针 = 覆盖块顶 − 0.2）：

- `h < 0.4`：覆盖块中心 `top − h/2` 高于探针 ⇒ 恒被跳过；黏液中心比探针低 ⇒ 只要进表
  就弹。1 层/2 层时脚离黏液顶近，收集盒必然够深 ⇒ 恒弹。
- `h ≥ 0.4`：覆盖块中心被选中（restitution = 0）；4 层时探针 `−59.7` 已低于黏液中心
  `−59.5`，连黏液都不进候选 ⇒ 恒不弹。

### 3.5 勘误与测量纪律

- **撤回**本轮之前的「填充判据不是单一阈值 / 反解 margin 互相矛盾」。判据是单一阈值，
  但阈值落在**收集盒下界**上，而不是「未裁剪落点 + 平移 margin」。当时按
  `target − margin < 黏液顶` 反解用的是 `+0x34`（请求位移）去配 `+0x18` 的盒，而盒里
  还含 `preY − 0.5681` 这一项；换用 §3.3 的 min 形式后 25/25。
- 盒是**粘的**：新盒被 `+0x18` 的旧盒包含时直接返回、不重建表。所以「表对应的盒」可能
  比当 tick 的并集盒更低，标签要取 `+0x18` 的实际值，不要用当 tick 的数据去重算。
- **按 tick 对齐**：resolver 在 T-1 和 T 各可能命中一次；标签只取抓到的表。
- 每次试次前回到静止地面再传送；从弹跳中途传送会改掉落地 tick 的请求位移（实测同一
  落差 `v` 从 −0.585 变成 −0.14），结果直接翻面。
- 每轮用 `blocks` 回读确认 `slime`/`snow_layer` 还在原位；`prep()` 的 fill 会静默失败。

**已排除（别再试）**：`BlockCollisionsSystem`（`0x14488F8E0`）注册的四个子系统不是
这张表的填充者——它们是另一条链（`0x1448A4FD0` 清
`BlockCollisionResolutionVectorComponent`（`0x2462ED53`，向量在表项 `+0x20`），
`0x1448A4570`/`0x1448A4360` 累加 `ActorSetPositionRequest`）。视图构造器
`0x1448A2B80/3FB0/4BD0/5100` 运行期 20 tick 内 0 命中，是注册期代码。


## 4. 判据与阈值

设覆盖块顶面与黏液上表面重合、高度 `h`，脚底在 `top`：

| 量 | 值 |
| --- | --- |
| 探针 | `top − 0.2` |
| 覆盖块中心 | `top − h/2` |
| 覆盖块被选中 ⇔ | `top − h/2 ≤ top − 0.2` ⇔ **`h ≥ 0.4`** |

按 1/16 档位（**证据列**：判据是 `[代码]`，雪层盒高是 `[实测]`，0.4 本身没有任何常量，
它是两者相除的推导）：

| h | 方块 | 结果 | 证据 |
| --- | --- | --- | --- |
| 0.0625 (1/16) | 地毯 | 弹 | 推断（同公式；本轮未单独实测） |
| 0.125 (2/16) | 雪 1 层 | 弹 | 实测（落差 0.25–6.0 全弹） |
| 0.1875 (3/16) | 打开的地板门 | 弹 | 推断（同公式） |
| 0.25 (4/16) | 雪 2 层 | 弹 | 实测（落差 0.25–6.0 全弹） |
| 0.375 (6/16) | 雪 3 层 | **临界：随落地相位翻转**（§3.4 的不等式） | 实测（逐档扫描 + 候选表抓取 + 填充代码） |
| 0.4375 (7/16) | 原版无此高度 | 不弹 | 公式 |
| 0.5 (8/16) | 雪 4 层 | 不弹 | 实测（落差 0.25–6.0 全不弹） |
| 0.5 (8/16) | 下半砖 | 不弹 | 推断（中心 0.25 ≤ 探针 0.3） |
| 1.0 | 整格 | 不弹 | 推断 |

补充两条口径：

1. 判据用**碰撞盒中心**，不是顶面；对碰撞盒不从方块底面开始、或高度分布不对称的自定义
   形状，要按中心重新算，不能直接用「顶面高度 < 0.4」。
2. `0.2` 与 Java `getOnPos(0.2F)` 同源，所以「地毯不挡弹」在 JE/BE 上逻辑一致。

## 5. 对旧结论的勘误

旧结论（会话内的 0.4 中心判据表）把 `6/16 = 0.375` 标成「弹」。数学部分成立
（中心 vs 探针、阈值 0.4），但 0.375 恰好落在临界外侧 0.0125，**不是稳定反弹**：
实测随落差在弹/不弹之间翻转，且由候选表是否含黏液块决定。旧表的 0.375 行应改成
「临界」。

## 6. 复现

静态：`idat` 打开 `%APPDATA%\levilauncher.exe\versions\<版本>\Minecraft.Windows.exe.i64`，
反编译 `0x148B5DB00`（判定）/ `0x141E144A0`（解析）/ `0x1431C2F50`（收集盒与填充）/
`0x1431DC500`、`0x1431DD080`（系统体与 runner）；或在 `.text` 里找 `movss` 引用
`0x14EA350B0`（0.080000117f）与 `addss` 引用 `-0.2f` 的站点。

定位手法（本轮用到的，可复用）：先 `hook_install` 解析器（`mem_arg=0
mem_offset=-88 mem_size=128`）拿到 `MoveRequest` 的运行时地址与候选表，再
`watch_set(addr=MR+0x60, size=8, mode="w", thread="both")` 抓「谁在改表尾指针」；
挂到的 6 个写点里 `0x1431C35FA`（`add [r13+0x60], 0x18`）就是 24 B 元素的
`push_back`，反编译它的宿主函数即得填充代码。

动态（harness）：3×3 黏液 + 石基座，`setblock ... snow_layer ["height"=N]`，
`teleport` 到 `top + 落差` 后 `record` 看落地后 `vy`。

动态（候选表）：`hook_install(va=base+0x1E144A0, mem_arg=0, mem_offset=-0x58,
mem_size=128)` 抓 `MR` 快照；盒下界读 `+0x1C`、请求位移读 `+0x34`、形状数
`(*(+0x60) − *(+0x58))/24`。

## 7. 预测器：只给落差就能算（2026-10-29 补）

把 §3.4 的判据接上自由落体积分，就不需要再开游戏扫描了。这个 build 的竖直积分是

```text
v0 = 0 ;  v_{k+1} = 0.98 · v_k + 0.0784        （0.0784 = 0.08 × 0.98）
y_{k+1} = y_k − v_{k+1}
```

落地那一 tick（`y_k − v_{k+1} ≤ 覆盖块顶`）的 `preY = y_k`、`δy = −v_{k+1}`，代进
§3.2 的盒公式即可。仓库里的可执行版本是 [`../../driver/bounce_predict.py`](../../driver/bounce_predict.py)：

```bash
py -3.11 driver/bounce_predict.py --layers 3 --drops 0.5,0.75,1.25,3.0
py -3.11 driver/bounce_predict.py --table        # 各层覆盖的「不弹」落差
py -3.11 driver/bounce_predict.py --validate     # 回放账本里的 60 行实测
```

核心两步（完整版含 picked/restitution 分支与 CLI）：

```python
def predict(cover_top, drop, slime_top=-59.0, auto_step=0.5625):
    y, v = cover_top + drop, 0.0
    while True:                                   # 落地 tick
        v = 0.98 * v + 0.0784
        if y - v <= cover_top:
            dy, feet = -v, cover_top
            break
        y -= v
    box_lo = min(y - auto_step * 1.01, y + dy - 0.2)
    h = cover_top - slime_top                    # 覆盖块高度（底面贴黏液顶）
    probe = feet - 0.2
    if cover_top - h / 2 <= probe:                # 覆盖块被选中
        return False                              # 雪/砖 restitution = 0
    return box_lo < slime_top and (slime_top - 0.5) <= probe
```

对质（全部「预注册」：先用公式算，再跑）：

| 组 | 样本 | `preY`/`δy` | 候选表 | 弹否 |
| --- | --- | --- | --- | --- |
| L3，0.5–3.5 步长 1/8 | 25 | 25/25 | 25/25 | 25/25 |
| L3，0.5625–2.8125 隔 0.25 | 20 | 20/20 | 20/20 | 20/20 |
| L2，15 档含 1/16 细档 | 15 | 15/15 | 15/15 | 15/15 |

也就是说**落进公式就能算准到 4 位小数**，包括 `preY` 本身。1/16 网格上「不弹」的落差
（覆盖块顶与黏液顶重合，落差从覆盖块顶量起，起点静止）：

| 覆盖 | 0.25–6.0 里不弹的落差 |
| --- | --- |
| 雪 1 层 (0.125) | 无（0.25–12 也无） |
| 雪 2 层 (0.25) | 1.125、1.5625、2.0625、2.6875、3.3125、4.0625、4.8125、5.6875 |
| 雪 3 层 (0.375) | 0.4375、0.6875、0.75、1.0、1.0625、1.125、1.4375、1.5、1.5625、1.9375、2.0、2.0625、2.5625、2.625、2.6875、3.1875、3.25、3.3125、3.9375、4.0、4.0625、4.6875、4.75、4.8125、5.5625、5.625、5.6875 |
| 雪 4 层以上 (≥0.5) | 全部 |

2 层那 8 个缝是**新预测**（旧表「2 层全弹」是 0.25 步长粗网格的漏检）：实测了其中
3 个（1.125 / 1.5625 / 2.0625，都不弹）和 12 个非缝落差（都弹），15/15。

两条前提，别外推：

1. 公式假设**从静止开始**从该高度落下（`v0 = 0`）。跳跃/被弹起后接手的高度带着初速，
   等价于从更高的地方落，结果要按 `(preY, δy)` 重新算，不能直接套落差表。
2. 0.2 / 0.5625 / 0.0784 都是本版本的运行时常数，换版本要重新从
   `docs/offsets`/roles 里取，不要当普适物理量。
