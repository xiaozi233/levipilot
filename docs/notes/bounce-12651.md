# 黏液块反弹与「上层覆盖方块」判据（1.26.51.01）

> 版本：`1.26.51.01`（LeviLamina 26.51.7），RVA 以映像基址 `0x140000000` 计。
> 目标问题：黏液块上覆盖方块时，什么条件下还能反弹；为什么 0.375 格高的雪层
> 「有时弹、有时不弹」。
> 账本：`skills/bedrock-re/findings/1.26.51.01/cases/slime-bounce-coverage/`。

## 0. 结论速览

- 判据是**形状中心 vs 探针**：解析器把实体 AABB 的 `minY` 减 `0.2` 当探针，
  在候选形状里取「中心 Y 不高于探针」的最高者；选中的方块决定 restitution。
- 覆盖块顶面在黏液上表面、高度 `h` 时，其碰撞盒中心在 `top − h/2`。探针在
  落地瞬间等于 `top − 0.2`，所以：**`h ≥ 0.4` 时覆盖块被选中（不弹），
  `h < 0.4` 时覆盖块被跳过、退回黏液（弹）**。
- 实测：1 层(0.125)/2 层(0.25) 任意落差都弹；4 层(0.5) 及以上从不弹；
  **3 层(0.375) 是唯一的临界高度**——雪层中心只比探针高 0.0125，结果取决于
  该次落地的候选表里还有没有黏液块，因此随落差翻转（同一落差可复现，不是随机）。
- 旧说法「6/16=0.375 一定弹」不成立；「中心判据 + 0.4 阈值」的数学成立。

## 1. 落地处理器与解析器

| 角色 | 地址（VA） | 作用 |
| --- | --- | --- |
| `@bounce_handler` | `0x148B5DB00` | 落地判定 + 取 restitution + 写 `ApplyRestitution` |
| `@block_pos_resolver` | `0x141E144A0` | 位置 → (方块坐标, 方块指针) |
| `@bounce_threshold_f32` | `0x14EA350B0` | `0.080000117f`（\|vy\| 门槛） |

处理器结构（与 45.01 的 `sub_146378200` 同构，只有地址变化）：

```c
if ((*flag & 2) == 0) {                       // 本 tick 没有需要跳过的标志
  vy = state_vector.vel.y;                    // [r8+0x1C]
  if (vy < 0 && fabsf(vy) >= 0.080000117f) {
    aabb_copy = *aabb;                        // 24 B，来自 AABBShapeComponent
    resolver(container, &out, &aabb_copy);    // container = MoveRequest + 0x58
    if (out.block) {
      coef = out.block->vtable[0x3E8](out.block, arg, &out.pos);   // 方块 restitution
      if (fabsf(coef) > 1.1920929e-7f) {
        entry = getComponent(0x7DF54114, entity);                 // ApplyRestitutionComponent
        cur   = entry->y;
        if (coef == -1.0f && cur > 0) { ... }                     // 蜂蜜块粘性分支
        else entry->y = fmaxf(coef * -vy, cur);
      }
    }
  }
}
```

解析器（`0x141E144A0`）的关键几行：

```c
v = aabb[1] + -0.2f;      // 探针 = minY - 0.2
aabb[1] = v; aabb[4] = v; // 查询盒 Y 压成一个点（X/Z 仍用盒中心）
for (shape in shapes) {              // 24 B/个，世界空间 AABB
  cy = (shape.maxY - shape.minY) * 0.5f + shape.minY;
  d  = v - cy;
  if (d < 0) continue;               // 中心高于探针 → 跳过
  if (d < best_d) { best = shape; best_d = d; }        // 取最高中心
  else if (d == best_d) { 水平中心更近者优先 }
}
if (best) { pos = floor(shape.min); block = refs[best_index]; }
```

实测候选表布局（客户端与服务端各一份，地址不同、内容同构）：

- 黏液块：`y = [−60, −59]`，中心 `−59.5`
- 3 层雪：`y = [−59, −58.625]`，中心 `−58.8125`
- 探针：`−58.825`（AABB `minY = −58.625`）→ 雪层被跳过，黏液被选中。

## 2. 实测矩阵

场地：3×3 黏液（y=−60）+ 3×3 石基座（y=−61），中心正落，`record` 逐 tick。
判据：落地后 `max(vy) > 0.02` 记为弹。

| 覆盖 | 高度 | 落差 0.25–6.0 格 |
| --- | --- | --- |
| 无 | 0 | 全弹 |
| 雪 1 层 | 0.125 | 全弹 |
| 雪 2 层 | 0.25 | 全弹 |
| 雪 3 层 | 0.375 | **翻转**见下 |
| 雪 4–5 层 | 0.5 / 0.625 | 全不弹 |

3 层（0.375）逐档（落差 → 结果）：

```text
0.25  弹   0.75  不弹   1.25  弹   1.75  弹   2.25  弹   2.75  弹
0.375 弹   0.875 弹     1.375 弹   1.875 弹   2.375 弹   2.875 弹
0.5   弹   1.0   不弹   1.5   不弹   2.0   不弹   2.5   弹     3.0   弹
0.625 弹   1.125 不弹                              2.625 不弹   3.0+  弹
```

同一落差重复 2–3 次结果一致；水平落点偏移 0–0.29、覆盖宽度 1/3/5 格都不改变结果
（说明不是「踩在边上」的问题，只由竖直方向的落地相位决定）。

## 3. 为什么 0.375 会翻转

Frida `Interceptor.attach` 挂在 `模块基址 + 0x1E144A0`，`onEnter` 里同步读：

- `args[2]`（AABB）：每次落地都是 `minY = 雪顶`，探针恒为 `雪顶 − 0.2`；
- `args[0]`（容器）：`[rcx]`/`[rcx+8]` 为形状数组的 begin/end，`[rcx+0x18]` 为方块指针数组。

实测（3 层雪）：

| 落差 | 落地时候选表 | 解析器选择 | 结果 |
| --- | --- | --- | --- |
| 1.0 | 只有雪层（n=1，cy=−58.8125） | 无（雪中心 > 探针） | 不弹 |
| 2.0 | 只有雪层（n=1） | 无 | 不弹 |
| 3.0 | 黏液 + 雪（n=2） | 黏液（cy=−59.5） | 弹 |
| 0.5 | 首帧 n=1、次帧 n=2 | 次帧选黏液 | 弹 |

2 层与 1 层在 0.5/1/2/3 格落差下每次落地都是 n=2，所以必弹。

也就是说：**0.375 时雪层能不能被选中只差 0.0125，结果完全由「这一 tick 的候选表里
还有没有黏液块」决定**；候选表由移动/碰撞系统按该 tick 的扫掠生成、落地后立刻清空
（事后 `mem_read` 读到 n=0），所以它随下落相位变化，看起来就像「有时可以有时不可以」。

## 4. 判据与阈值

设覆盖块顶面与黏液上表面重合、高度 `h`，脚底在 `top`：

| 量 | 值 |
| --- | --- |
| 探针 | `top − 0.2` |
| 覆盖块中心 | `top − h/2` |
| 覆盖块被选中 ⇔ | `top − h/2 ≤ top − 0.2` ⇔ **`h ≥ 0.4`** |

按 1/16 档位（**证据列**：判据是 `[代码]`，雪层盒高是 `[实测]`，0.4 本身没有任何常量，
它是两者相除的推导）：

| h | 方块 | 结果 | 证据 |
| --- | --- | --- | --- |
| 0.0625 (1/16) | 地毯 | 弹 | 推断（同公式；本轮未单独实测） |
| 0.125 (2/16) | 雪 1 层 | 弹 | 实测（落差 0.25–6.0 全弹） |
| 0.1875 (3/16) | 打开的地板门 | 弹 | 推断（同公式） |
| 0.25 (4/16) | 雪 2 层 | 弹 | 实测（落差 0.25–6.0 全弹） |
| 0.375 (6/16) | 雪 3 层 | **临界：随落地相位翻转** | 实测（逐档扫描 + 候选表抓取） |
| 0.4375 (7/16) | 原版无此高度 | 不弹 | 公式 |
| 0.5 (8/16) | 雪 4 层 | 不弹 | 实测（落差 0.25–6.0 全不弹） |
| 0.5 (8/16) | 下半砖 | 不弹 | 推断（中心 0.25 ≤ 探针 0.3） |
| 1.0 | 整格 | 不弹 | 推断 |

补充两条口径：

1. 判据用**碰撞盒中心**，不是顶面；对碰撞盒不从方块底面开始、或高度分布不对称的自定义
   形状，要按中心重新算，不能直接用「顶面高度 < 0.4」。
2. `0.2` 与 Java `getOnPos(0.2F)` 同源，所以「地毯不挡弹」在 JE/BE 上逻辑一致。

## 5. 对旧结论的勘误

旧结论（会话内的 0.4 中心判据表）把 `6/16 = 0.375` 标成「弹」。数学部分成立
（中心 vs 探针、阈值 0.4），但 0.375 恰好落在临界外侧 0.0125，**不是稳定反弹**：
实测随落差在弹/不弹之间翻转，且由候选表是否含黏液块决定。旧表的 0.375 行应改成
「临界」。

## 6. 复现

静态：`idat` 打开 `%APPDATA%\levilauncher.exe\versions\<版本>\Minecraft.Windows.exe.i64`，
反编译 `0x148B5DB00` / `0x141E144A0`；或在 `.text` 里找 `movss` 引用
`0x14EA350B0`（0.080000117f）与 `addss` 引用 `-0.2f` 的站点。

动态（harness）：3×3 黏液 + 石基座，`setblock ... snow_layer ["height"=N]`，
`teleport` 到 `top + 落差` 后 `record` 看落地后 `vy`。

动态（候选表）：Frida `Interceptor.attach(base + 0x1E144A0, { onEnter })`，
读 `args[2]` 的 6 个 float 与 `args[0]` 的 `{begin, end, refs}`；
仓库内要长期保留这个能力，建议给 `HookHit` 增加「按参数号 + 偏移采 N 字节」字段，
而不是依赖外部注入。
