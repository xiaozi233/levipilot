# 创造飞行物理：水平/竖直递推与 `0.34125` 滑行阻力（`1.26.51.01`）

> 版本：`Minecraft.Windows.exe` `1.26.51.01`（LeviLamina `26.51.7`，`image_base = 0x140000000`）。
> 证据约定：`[代码]` 反汇编控制流/数据流；`[常量]` `.rdata` 浮点、组件哈希、注册点；`[实测]` LeviPilot 逐 tick 录制与 ECS 回读；`[推断]` 由直接证据补出的环节。
> 复现脚本：[`verify_creative_flying.py`](../../skills/bedrock-re/findings/1.26.51.01/cases/creative-flying-12651/probes/verify_creative_flying.py)。原始数据：gitignored `out/creative-flying-1.26.51.01.json`（账本 `r01-003`、`r02-013`、`r03-015` 均 `exit: 0`；正文数字取自 `r03-015`）。
> **勘误**：Round 3 修正了玩家摩擦消费链（`0x142DFE950` → `0x142DE2086`）、竖直输入位与 `0.75` 分支、§5 相位表标签；旧描述见 `journal.jsonl` 的 `erratum` 记录。
> 相位口径：录制的 `vx/vy/vz` 是**已完成位移**（`mPos − mPosPrev`）；`StateVectorComponent +0x18/+0x1C/+0x20` 是本拍摩擦后的**待执行位移** `mPosDelta`，两者差一个 `0.91`（见 §5）。

## 1. 系统清单与同 tick 顺序

### 1.1 三个直接相关系统

| 系统 | 名字字面量 | vtable | slot[5] / slot[6] | 注册点 |
| --- | --- | --- | --- | --- |
| `PlayerFlyingMoveSpeed` | `0x14EC92A20` | `0x14E85B520` | `0x142E0F7B0` / `0x142E100E0` | setup `0x142DE5AD0`，调用点 `0x146826130` |
| `MobMovementDrag::PlayerFlying` | `0x14EC4A36D` | `0x14E85B070` | `0x142DF5500` / `0x142DF5E50` | setup `0x142DE1050`，调用点 `0x1468265AF` |
| `MobMovementFriction::PlayerFlying` | `0x14EC4A34B` | `0x14E85B1C0` | `0x142DFDBB0` / `0x142DFE950` | setup `0x142DE21D0`，调用点 `0x1468265BB` |
| `VerticalFlySpeedControlSystem` | `0x14EC34CB2` | `0x14E83ACD0` | `0x1428DEF50` / ret | 姿态组 `0x14681DA00` 内 `0x1468200EA` |

`PlayerFlyingTravelComponent`（`0x42910726`）是三者共用的标记/数据组件；`PlayerFlyingMoveSpeed` 还访问
`MovementAbilitiesComponent`（`0x6DE78DC5`）、`ADF`（`0xC67426F3`）与 `MobTravelComponent`（`0x39CF8D64`）。
摩擦系统的视图只含 `PlayerFlyingTravelComponent` 与 `DiscardFrictionFlagComponent`（`0x40BED7F4`），
注册块的 `movabs 0x4291072640BED7F4`（`0x142DE27A8`）就是这两项 `[常量]`。

### 1.2 顺序的静态证明

主 setup `0x146822800` 内按下列先后调用注册函数（同一函数体、同一类别向量、`mode=1` 追加、正序遍历）：

```
0x1468230DA  call 0x14681DA00   ; 姿态组：含 VerticalFlySpeedControlSystem(0x1468200EA)
...
0x146826130  call 0x142DE5AD0   ; PlayerFlyingMoveSpeed
0x1468264F3  TravelMoveRequestSystem（vtable 0x14EA52070，slot[5] 0x1490DBD90）
0x146826555  call 0x14681AC20   ; 移动碰撞组
0x14682658B  call 0x142DE0950   ; 水/岩浆 drag
0x146826597  call 0x142DE58F0   ; LevitateSystem
0x1468265A3  call 0x142DE36A0   ; 重力（地面/水/岩浆）
0x1468265AF  call 0x142DE1050   ; MobMovementDrag::PlayerFlying
0x1468265BB  call 0x142DE21D0   ; MobMovementFriction::PlayerFlying
```

因此**竖直控制先决定 `0.375` 覆盖值，摩擦/阻力在移动之后把它消费掉**；`PlayerFlyingMoveSpeed`
在碰撞与阻力之前写入本拍速度。注册链的集合语义（`mode & 1` 追加到 `+0x38`、正序遍历）见
[`pipeline.md`](../../skills/bedrock-re/references/pipeline.md) §1，本版逐项复核了 vtable 与调用点。

## 2. 水平运动

### 2.1 递推与稳态

```
v_{n+1} = 0.91 · v_n + 0.049          [格/tick]
v_∞     = 0.049 / (1 − 0.91) = 0.54441
```

`[实测]`（`r01-003`，45 tick 前向）：

| 量 | 值 |
| --- | --- |
| 摩擦拟合 `f` | **`0.90999898`** |
| 加速度拟合 `a` | **`0.04899740`** |
| 拟合最大残差 | `3.50e-06` |
| 45 tick 采样稳态 | `0.53353310`（约 98% 收敛） |
| 解析稳态 `a/(1−f)` | **`0.54440946`** |

第一拍从静止直接得到 `0.04899597`，第二拍 `0.09358597 = 0.91×0.04899597 + 0.0489974`，与递推一致。

### 2.2 疾跑与斜走

| 场景 | `f` | `a` | 稳态 | 相对直行 |
| --- | --- | --- | --- | --- |
| 前进 | `0.90999898` | `0.04899740` | `0.54440946` | `1.0` |
| **前进 + 疾跑键** | `0.91000020` | `0.09799378` | `1.08882224` | **`2.000006`** |
| 斜走 `W+A` | `0.91000002` / `0.90999891`（两轴） | — | 合成 `0.54444384` | **`1.000063`** |

疾跑的 `2.0` 是**精确常数**，不是属性修饰：`PlayerFlyingMoveSpeed` 的逐实体 worker
`0x142E0F730` 读 `ADF` 的 `bit3`，再用 `{2.0f, 1.0f}` 表选择乘数 `[代码]`：

```
0x142E0F790  test byte ptr [r8], 8        ; ADF bit3 = SPRINTING
0x142E0F794  sete al                      ; 疾跑 → al=0；否则 al=1
0x142E0F797  lea rcx, [0x14E85AF40]       ; {2.0f, 1.0f}
0x142E0F79E  mulss xmm0, [rcx + rax*4]    ; flySpeed × {2 | 1}
0x142E0F7A3  movss [r9 + 0xC], xmm0       ; → MobTravelComponent+0x0C
```

斜走不加速：两轴各自按同一 `0.91/0.049` 递推，合成模长与直行相同。

### 2.3 `flySpeed` 与 `0.049`

`MovementAbilitiesComponent`（`0x6DE78DC5`）的 ECS 原始字节 `+0x08 = 0x3D4CCCCD`，即 **`0.05f`** `[实测]` `[常量]`。
实测加速度 `0.04899740` 与 `0.05` 的比值是 `0.97995`，即 `0.049 ≈ 0.05 × 0.98`。

`0.98f`（`0x14E7E1500`）在本版确实存在并在移动代码里被引用（`0x142DF179C` 等），但**没有定位到
"飞行加速度 × 0.98" 的那一条指令**；因此 `a = flySpeed × 0.98` 的写法标 `[推断]`，
`a = 0.049` 本身是 `[实测]`，`flySpeed = 0.05` 是 `[常量]`。

> 反例检查：若按 `a = flySpeed` 建模，稳态应为 `0.05/0.09 = 0.5556`，比实测 `0.54441` 高 `2.0%`，
> 在 45 tick 的收敛曲线上稳定可见，不是采样误差。

### 2.4 松键滑行：`0.34125` 的来历

`[实测]`（同一录制，峰值 `0.53189468` 之后逐拍比）：

| 拍 | 比值 |
| --- | --- |
| 第 1 拍 | **`0.90999978`** |
| 第 2 拍 | **`0.34124870`** |
| 第 3 拍 | `0.34125499` |
| 第 4 拍 | `0.34122902` |
| 第 5 拍 | `0.34133280` |
| 第 6 拍 | `0.34108077` |

float32 递推预测：`0.53189468 × 0.91 = 0.48402417`（实测 `0.48402405`）、
`0.48402417 × 0.91 × 0.375 = 0.16517322`（实测 `0.16517258`），残差 `< 2e-05`。

**`0.34125` 不是独立常量** `[常量]`：

- `driver/pe_map.py --find-f32 0.34125` 全库 4 处：`0x14E9794BC`、`0x14E9794CC`、`0x14E979F90`、`0x14E979FB0`；
- 四处 `--xrefs` 全部 **0 条 `.text` 引用**，且都落在方块碰撞高度表（相邻值是 `0.46625 / 0.47125 / 0.28375 / 0.56` 一类的形状高度），与飞行无关；
- 真正参与运算的是 `0.91f`（`0x3F68F5C3`）与 `0.375f`（`0x3EC00000`）。

**消费链（玩家路径，而不是 Vex 分支）** `[代码]`：

```
MobMovementFriction::PlayerFlying::slot[6] = 0x142DFE950
0x142DFEA78  mov edx, 0x0CBB7191          ; 查 FrictionModifierOverrideComponent
0x142DFEA96  mov edx, 0x52857D3D          ; 查 VexFlagComponent（恼鬼标记）
0x142DFEB5D  add r8, [r9 + rdx]           ; 覆盖组件实例 → r8
0x142DFEB78  mov dword [rsp+0x20], 0x3F68F5C3   ; 0.91f 作为第 5 个参数
0x142DFEB86  call 0x142DE2010

0x142DE201D  cmp byte [rsp+0x50], 0       ; 第 7 个参数 = Vex 位
0x142DE2022  je 0x142DE207A               ; 玩家（非 Vex）走这里
0x142DE2024..0x142DE2075                  ; Vex 专属分支（含 0x142DE2048 的 0.91f）

玩家分支 0x142DE207A：
0x142DE2080  movss xmm0, [rsp+0x40]       ; 0.91f
0x142DE2086  test r8, r8
0x142DE208B  movss xmm2, [r8]             ; 0.375f
0x142DE2090  mulss xmm3, xmm2             ; 0.375
0x142DE214B  mulss xmm3, xmm0             ; 0.375 × 0.91 = 0.34125
0x142DE2176  mulss xmm4, xmm0 ; movss [rax+0x18]   ; mPosDelta.x
0x142DE218A  mulss xmm2, xmm3 ; movss [rax+0x20]   ; mPosDelta.z
```

`0x142DE201D` 读的 `VexFlagComponent` 只区分恼鬼；**玩家从不经过 `0x142DE2048`**。
`r8` 在该组件缺失时为 0（走 `0x142DE2099` 的方块摩擦口），存在时就是 `0.375` 的实例指针。
进入玩家分支时 `xmm3` 是调用方传入的系统基值（`0x142DFEAF5 movss xmm3, [r13+0x1C]`）；
玩家飞行取 `1.0`（由 `0.375 × 1.0 × 0.91 = 0.34125` 的实测乘积反推），故这一支就是
`0.375 × 0.91`。

**`0.375` 的写点与输入门控** `[代码]`（`VerticalFlySpeedControlSystem` 逐实体 lambda `0x1428A7140`）：

```
0x1428A7170  movss xmm0, [rdx+0x24]       ; 水平移动模拟量 X
0x1428A7175  movss xmm1, [rdx+0x28]       ; 水平移动模拟量 Y
0x1428A7196  movss xmm0, 0.01f
0x1428A719E  ucomiss xmm0, xmm3
0x1428A71A1  jbe 0x1428A72D4              ; 水平输入 ≥ 0.01 → 整段跳过

0x1428A7286  mov ecx, [rbx]               ; 输入模式
0x1428A7297  mov dword [r15+r14*4], 0x3EC00000   ; 键鼠：覆盖值 = 0.375
0x1428A72C9  mov dword [r15+r14*4], 0x3F400000   ; 其它模式：覆盖值 = 0.75

0x1428A72A2  movzx eax, word [rdi+0x60]   ; 竖直控制位（跳/潜行）
0x1428A72A6  test al, 4  → 跳过
0x1428A72AA  test al, 8  → 跳过
0x1428A72B0  and eax, 0xC → 跳过
0x1428A72B5  movss xmm0, [rsi+0x1C]
0x1428A72BA  mulss xmm0, 0.375f            ; 仅在没有竖直键时再乘一次
```

即：**水平输入 ≥ `0.01` 时，整个覆盖写入与 `mPosDelta.y × 0.375` 都被跳过**（水平摩擦回到
`0.91`）；没有水平输入时写入覆盖值 —— 键鼠 `0.375`（`0.91 × 0.375 = 0.34125`），
其它输入模式 `0.75`（`0.91 × 0.75 = 0.6825`）。`[rdi+0x60]` 的跳/潜行位只决定
**竖直**分量是否再乘 `0.375`，与水平切换无关。

**切换条件**（`r03-015` 实测，全部来自同一 JSON）：

| 松键后保持的按键 | 首拍比 | 持续比 | 竖直侧 |
| --- | --- | --- | --- |
| 什么都不按 | `0.91` | **`0.34125`** | `vy` 每拍 ×`0.225` |
| 按住跳跃 | `0.90999978` | **`0.34125185`** | 进入 `+0.15` 加速（极值 `+0.37273216`） |
| 按住潜行 | `0.90999978` | **`0.34125185`** | 进入 `−0.22` 加速（极值 `−0.54667473`） |
| 按住前进（不松 W） | `0.91` | `0.91`（持续加速，稳态 `0.5444`） | 松跳首拍 `0.5999983` |

最后一行是本次补测的关键对照：**W 保持时松跳，竖直首拍是 `0.6` 而不是 `0.225`**，
因为 `0x1428A71A1` 已因水平输入跳过 `×0.375`。

## 3. 竖直运动

### 3.1 递推

```
vy' = 0.6 · vy + a      a = +0.15（跳） / −0.22（潜行） / 0（同按）
vy_∞ = +0.375（跳） / −0.55（潜行）
```

`[实测]`（`r03-015`）：

| 场景 | 阻力拟合 | 加速度拟合 | 残差 | 稳态 |
| --- | --- | --- | --- | --- |
| 按住跳跃 | `0.59999844` | **`0.15000059`** | `7.71e-07` | **`+0.375`** |
| 按住潜行 | `0.59999994` | **`-0.22000002`** | `1.05e-06` | **`-0.54999924`** |
| 跳 + 潜行 | — | — | — | `vy ≡ 0`、`y` 漂移 `0` |

从 `+0.375` 松开跳跃，首拍比 **`0.22499975`**（`= 0.6 × 0.375`），即竖直方向也吃到了 §2.4 的 `0.375` 覆盖。

### 3.2 静态来源

`0x1428A7140` 的位累加 `[代码]` `[常量]`：

```
0x1428A72F2  test al, 4   → 0x1428A72F6  addss xmm0, 0.15f   (0x14E6AE4DC)
0x1428A7309  test al, 8   → 0x1428A73B2  addss xmm0, -0.22f  (0x14E83A410)
0x1428A7300  test cl, 8   → 0x1428A73A2  addss xmm0, 0.05f   (0x14E6AE530)
0x1428A7311  test cl, 4   → 0x1428A7316  addss xmm0, -0.15f  (0x14E6AE4E8)
0x1428A7382  mulss xmm0, xmm1            ; × 属性表值（compare [rax+0x10], 7）
0x1428A7386  addss xmm0, [rsi+0x1C]      ; += mPosDelta.y
0x1428A738B  movss [rsi+0x1C], xmm0
```

竖直控制位与水平模拟量分开：`[rdi+0x60]` 的 bit2/bit3 与 `[rdx] & 0xC` 是跳/潜行，
只影响 §2.4 的 `mPosDelta.y × 0.375` 与下面的清零；水平门控在 `0x1428A7170..0x1428A71A1`。
`0x1428A72D4` 读 `[rdx+0x60]`，当 `(~eax) & 0xC == 0`（跳与潜行位同时存在）时
`0x1428A72E0` 直接把 `[rsi+0x1C]` 清零——这就是"同按跳+潜行悬停锁"。

竖直阻力 `0.6` 来自 `MobMovementDrag::PlayerFlying` 的 lambda `0x142DF50B0`：

```
0x142DF50B0  movss xmm0, 0.4f             ; 0x14E85AF38
0x142DF50B8  cmp byte [rdx+0x44], 0
0x142DF50BE  mulss xmm0, [rdx+0x40]       ; 有方块因子时 0.4 × blockFactor
0x142DF50D5  subss xmm3, xmm1             ; 1 − 0.4 = 0.6
0x142DF50E1  mulss xmm2, [r8+0x1C]
```

飞行路径 `[rdx+0x44] == 0`，所以就是 `1 − 0.4 = 0.6`。

### 3.3 重力与落地

飞行时竖直位移只由上面的递推与 `0.375` 覆盖决定，**没有重力项**：悬停（无竖直键）时
`vy` 在若干拍内归零并保持 `0` `[实测]`。
**落地不会清 `flying`**：从 `-30` 持续潜行下降到脚 `-39.0` 后，连续 9 次采样
`flying=true`、`vy=0`、`on_ground=true`；只有再次双击空格（或撤销 `MayFly`）才会退出 `[实测]`。

## 4. 特殊对照

| 对照 | 结果（`r03-015`） | 结论 |
| --- | --- | --- |
| 贴地石面（脚 `-59.5`，离地 `0.5`） | `f=0.90999997`、`a=0.04899734` | 与高空一致 |
| 贴地蓝冰 | `f=0.90999997`、`a=0.04899734` | **逐位相同**，不读下方方块摩擦 |
| 水中（`in_water=true`，18 个湿样本） | `f=0.91000132`、`a=0.04899686` | 与空中 `0.04899740` 差 `5.4e-07` |
| 迅捷 II（`amplifier=1`） | `accel` 比 `0.999999` | 无影响 |
| 缓慢 II（`amplifier=1`） | `accel` 比 `0.999999` | 无影响 |

水中飞行**不叠加**水体阻力/浮力：竖直仍按 `0.6/±0.15/-0.22` 走，水平仍按 `0.91/0.049` 走。
这与"飞行优先级高于液体"的实现一致：飞行摩擦/阻力系统的视图不含液体组件，液体系统本身
只在非飞行分支生效（后者属既有流体结论，本 case 未重复拆解）。

## 5. `mPosDelta` 相位

`[实测]`（`record_start watch=[0x1B5D5238+0x18/+0x1C/+0x20]`，59 个连续加速拍）：

| 量 | 值 |
| --- | --- |
| `median(abs(vx_{n+1} − (mPosDelta_n + a)))` | **`8.92e-07`** |
| `max(abs(vx_{n+1} − (mPosDelta_n + a)))` | `1.07e-05` |
| `mPosDelta / vx` 中位数 | **`0.90999953`** |
| 逐拍加速度中位数 `vx_{n+1} − mPosDelta_n` | **`0.04899749`** |
| 同段递推拟合残差（连续拍） | `1.49e-05` |

即：

```
本拍已完成位移  vx_n   = 上一拍 mPosDelta_{n-1} + a
本拍待执行位移  pdx_n  = 0.91 · vx_n        （空闲时再 × 0.375）
```

这解释了为什么"拿 `mPosDelta` 当速度"会差一个 `0.91`：它是**摩擦后、尚未应用**的位移，
而录制的 `vx` 是本拍已应用的位移。
