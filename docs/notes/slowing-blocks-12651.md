## 1. `BlockMovementSlowdownMultiplierComponent` 体系与消费时序

### 1.1 组件、免疫与 `0.998^3` 效果盒

- **核心组件与标签** `[代码]` `[常量]`：
  - `BlockMovementSlowdownMultiplierComponent`（ECS hash `0xf6091f58`，`(float x, float y, float z)`）；
  - `BlockMovementSlowdownAppliedComponent`（ECS hash `0xe315e68e`，标记位）；
  - `BlockMovementSlowdownImmunityComponent`（ECS hash `0x8340ec7f`，注册与读取见 `0x1481c51a0`，对目标方块全免疫时三路写入均直接跳过）。
- **效果盒 `EntityInsideSystem`**（注册点 `0x146838546`，实现 `0x1463ae5a0` → `0x1433df8b0`）`[代码]` `[常量]`：
  - 先取实体 AABB，再将其最小坐标 **`+0.001f`**（`0x14e69fdc0`）、最大坐标 **`-0.001f`**（`0x14e7ca488`），随后对缩窄后的范围做 `floor` 枚举所有重合方块。
  - 等效于每个减速方块的生效盒在六个面上各向内收缩 `0.001` 格，有效体积为 **`0.998 × 0.998 × 0.998`**。

### 1.2 系统注册顺序与写入规则（`0x1468353c0`）

主系统注册函数 `0x1468353c0` 内按顺序登记以下实体系统 `[代码]`：

1. **`EntityInsideSystem`**（`0x146838546`）：收集本帧缩窄 `0.001f` 后与玩家相交的方块集合（甜浆果丛写 `InsideBlockComponent (0xc1c8fb69)` 与 `InsideSlowingSweetBerryBushBlockComponent (0x03abf17e)`；蜘蛛网与细雪分别收集）。
2. **`InsideSweetBerryBushBlockSystem`**（`0x14683857d`）与 **`SweetBerryBushMovementSlowdownSystem`**（`0x1468386a2`，实现 `0x14c606140..0x14c606333`，虚表 `0x14eb405b0`）：读取 `0x03abf17e`，向 `0xf6091f58` 写入 **`(0.8f, 0.75f, 0.8f)`**。
3. **`InsideGenericBlockSystem`**（`0x146838f07` 等）：
   - **细雪写入点** `0x1463ad860..0x1463ada52`（核心写函数 `0x1463c7650` / `0x1463c0f90`）：写入 **`(0.9f, 1.5f, 0.9f)`**（`0x14e69f370`, `0x14e6ae490`）并加 `0xe315e68e`（闭合 [`climb-blocks-12651.md`](climb-blocks-12651.md#6-未闭合静态边界诚实披露) 原留白项）；
   - **蜘蛛网写入点** `0x1463ada60..0x1463adc52`（`0x1463c7850` / `0x1463c0f90`）：写入 **`(0.25f, 0.05f, 0.25f)`**（`0x14e61e140`, `0x14e6ae530`）并加 `0xe315e68e`。
4. **多方块叠加写入（分量取小 `minss`）**：上述三个写入点共用同一合并逻辑——若 `0xf6091f58` 当前任一分量 `< FLT_EPSILON`（`1.19209e-7f`），直接覆盖；否则对 `x/y/z` 逐分量执行 `minss` 取更小值。
   - **注意细雪的叠加特例**：细雪的 `y = 1.5f` 与蜘蛛网 `y = 0.05f` 重叠时取 `min(0.05, 1.5) = 0.05f`（即 `0.25, 0.05, 0.25`）；与甜浆果丛重叠时取 `(0.80, 0.75)`。
5. **免疫清除系统**：
   - **`immuneWitherBoss`**（`0x14683878e` → `0x1448906f0`）：清空凋灵的 `0xf6091f58` 并移除 `0xe315e68e`；
   - **`immunePlayer`**（`0x14683898d` → `0x1448907a0`）：检查 `MovementAbilitiesComponent (0x6de78dc5) +4`（`mFlagValues`）是否满足 **`(mFlagValues & 5) == 5`**（`not eax; test al, 5; jne skip`）。由 `0x1428af4a0` 与映射表 `0x14e839cdc` 查明：`bit 0 = AbilitiesIndex::Flying (9)`、`bit 2 = AbilitiesIndex::Instabuild (11)`（`MayFly(10) -> bit 1`、`OperatorCommands(6) -> bit 3`、`NoClip(17) -> bit 4`、`WorldBuilder(16) -> bit 5`）。**因此仅当创造玩家处于飞行状态（`Flying=1 && Instabuild=1`）时才会清空减速；站在地面上的创造玩家仍受减速影响。**
   - **`resistantMob`**（`0x146838a5c`）：蜘蛛等抗性生物免疫路径。
6. **清零摔落距离与清扫**：`adjustFallDistance`（`0x146838ae7` → `0x1448a8d30`）在减速生效时清零 `FallDistanceComponent (0xce6b34f6)`；`createCleanupSystem`（`0x146838b1e`）做每拍清理。
7. **移动消费与归零 `applySlowdownOnMove`**：注册点 `0x14681ad26` → `0x1448a98c0`。在移动阶段将 `MoveRequestComponent (0x4c8f7288) +0x3c/+0x40/+0x44`（待应用的位移请求）分别乘以 `(mx, my, mz)`，随后把 `StateVectorComponent::mPosDelta (+0x18/+0x1C/+0x20)`（等待下一拍继续应用的残留位移量）**每拍清零**，并把 `0xf6091f58` 重置回 `0`（故离开减速方块后**无速度惯性残留**）。

## 2. 蜘蛛网、甜浆果丛与细雪细节机制

### 2.1 甜浆果丛：为何 `growth = 0` 也减速且免摔，却不伤血

反汇编甜浆果丛触碰处理函数 `0x1495cca80..0x1495cce58` `[代码]`：

- 函数开头无条件向玩家写入 `InsideBlockComponent (0xc1c8fb69)` 与 `InsideSlowingSweetBerryBushBlockComponent (0x03abf17e)`，**不检查 `growth` 状态**；
- 随后才检查方块状态 `growth`（`0x1495ccb78` / `0x1495ccbac`）：仅当 **`growth > 0`** 时才继续走实体类型过滤并调用伤害函数 `0x14244a700`。
- 因此：幼苗期（`growth = 0`）虽然完全没有荆棘伤害，但同样触发 `0.80 / 0.75` 减速与 `adjustFallDistance` 摔落免伤；且仅在移动时发生刺伤。

### 2.2 细雪碰撞与跌落下陷判定（`PowderSnowBlock::getCollisionShape`）

反汇编 `0x149952000..0x149952292`（虚表 `0x14ea77ff0`）`[代码]` `[常量]`：

1. 若 `entity == nullptr`、`feetPos.y < float(blockPos.y + 1) - FLT_EPSILON` 或 `entity->isDescending()`，直接返回空碰撞盒（穿入方块内部）。
2. 检查 **`entity->getFallingHeight() > 2.5f`**（`0x1499521a2`，常量 `0x14e76b088`）：
   - 若大于 `2.5` 格：返回局部降顶盒 `[0, 0, 0 .. 1, 0.9, 1]`（静态常量 `0x151db9d7c`，初始化于 `0x142deb0e0`）。
   - 该盒顶面低于方块顶面 `0.1` 格，玩家碰撞箱当拍压入 `blockPos.y + 0.9`，下一拍随即满足 `feetPos.y < blockPos.y + 1 - eps` 而继续向整块细雪内部以 `-0.1176` b/t（`-0.0784 × 1.5`）下沉，哪怕穿着皮革靴也会跌入雪中（同时因 `onFallOn` 为空实现与 `adjustFallDistance` 保护而保持 `0` 摔落伤害）。
3. 若 `fallingHeight <= 2.5f`：仅当实体为 `FallingBlock (0x42)` 或满足 `canStandOnPowderSnow`（ECS `0xb639c3b7 || 0x4eac501f`，经 `0x1412e2100` / `0x148245a10` 判定，含玩家穿皮革靴）时返回完整 `[0, 0, 0 .. 1, 1, 1]` 支撑方块。
4. 此项同时闭合 [`climb-blocks-12651.md`](climb-blocks-12651.md#6-未闭合静态边界诚实披露) 中原标 `unresolved` 的第二个细雪 VA 留白。

## 3. 细雪冰冻（`FreezingSystem`）数值与空中免疫原因

反汇编 `FreezingSystem::tickSystem`（注册点 `0x1467f32bb`，实现 `0x14665efa0..0x14665f8af`）`[代码]` `[常量]`：

1. **判定盒与免疫门控**：
   - 使用与减速方块完全一致的 **`+0.001f / -0.001f` 缩窄盒**（`0x14665f214..0x14665f28f`）判定玩家是否位于细雪内；
   - 以下情形跳过蓄冻并直接走解冻分支（`0x14665f3e2`）：持有 `FreezingImmuneComponent (0x11c35afb)`、穿戴任意皮革护甲写上的 `FreezingImmuneFromEquipmentComponent (0x578b6d03)`、`IsDead (0x710a62c4)`、游戏模式为 **`Spectator (6)`** 或 **`Default (5)` 且世界默认为 `Spectator`**（`0x14665f1fb..0x14665f20e`，`0x14253dc40`），或无法受冻（含创造模式虚表判定 `0x14665f05a` / `0x14665f5c4`）。
2. **归一化蓄冻进度 `p ∈ [0, 1]`（`FreezingComponent (0x47e62980)+0`）**：
   - 在细雪内且非免疫：每服务端 tick **`+ 1/140`**（`0x14e942878 = 0x3bea0ea1`），上限 `1.0f`（共需 `140` 刻 = `7.0` 秒满冻）；
   - 离开细雪（或免疫后）：每服务端 tick **`- 2/140`**（`0x14e9962cc = 0xbc6a0ea1`），下限 `0.0f`（共需 `70` 刻 = `3.5` 秒完全解冻）；当 `p <= FLT_EPSILON` 时移除 `FreezingComponent`。
3. **冰冻减速仅作用于地面移动速度（不影响空中）**：
   - 系统在玩家 `SharedAttributes::MOVEMENT_SPEED (0x151dc5488)` 上维护名称为 `"Freeze effect"`（`UUID @ 0x151e527a0`，函数 `0x142087210`）的瞬态 `AttributeModifier`：
     - `amount = -0.05f * p`（`0x14e7d1af8 = 0xbd4ccccd`），`Operation = 0 (Addition)`，`Operand = 2`。
     - 在 `AttributeInstance::calculateValue`（`0x142859e10`）中，Stage 0 乘法之前先叠加 Addition，于是玩家基础移速 `0.10` 变为 **`0.10 - 0.05 * p = 0.10 * (1 - 0.5 * p)`**，随后再进入 Stage 2 乘以疾跑（`1.3`）与药水倍率；满冻 `p = 1.0` 时地面移动（含跳跃起跳那拍地面加速）降为 **`50%`**。
     - 该修饰符**不修改 `AirSpeedComponent (0x9b8f9061)`**（空中基础加速度保持 `0.02` b/t²），因此玩家起跳脱离地面后的逐拍空中加速不受冰冻衰减。
4. **冻伤周期**：
   - 当 **`|p - 1.0f| <= FLT_EPSILON`**（已满冻）时，系统以 `imul 0x66666667` 检查实体生命刻计数 **`[rdi + 0x198] % 40 == 0`**（`0x14665f55b..0x14665f57e`），即每 **`40` 刻**（`2.0` 秒）造成一次 **`1.0f`** 冻伤（若持有 `FreezingVulnerableComponent (0x2c8f0870)` 则造成 `5.0f`，`0x14e9962d0`）。

## 4. 灵魂沙（`minecraft:soul_sand`）机制澄清

反汇编三个 `.text` 灵魂沙检查函数（`0x14666cee0..0x14666d222`、`0x14666f530`、`0x1466588d0`）`[代码]` `[常量]`：

1. **触发条件与 `+0.1` 抬升采样盒**：
   - 仅当实体处于地面（`on_ground`）且未持有 **`SoulSpeedEnchantFlagComponent (0x6da32dd7)`**（穿戴灵魂疾行靴）时生效；
   - 采样方块坐标固定为 **`(floor(mPos.x), floor(AABB.min.y - 0.1f), floor(mPos.z))`**，与地面滑度（slipperiness）复用同一偏移量——故站在上方薄地毯（顶面 `+0.0625 < 0.1`）上仍命中下方灵魂沙，而站在半砖（`+0.5 > 0.1`）上则命中半砖自身而免受减速。
2. **准确乘数 `0.543991×` 与地面阻力维持 `0.546`**：
   - 命中 `minecraft:soul_sand`（hash `0x93e2bb1cb7f99fc6`）时，将基础方块摩擦 `0.6f` 乘以 **`1.225f`**（`0x14e9962c8`）得 `0.735f`，令中间摩擦系数 `m = 0.735 × 0.91 = 0.66885f`；
   - `MobTravelComponent (0x39cf8d64) +0x0c` 所承受的地面加速度缩放因子为 **`(0.546f / m)^3 = (1 / 1.225)^3 ≈ 0.54399103`**（即约为普通石块的 **`54.4%`**）；
   - **关键区分**：`ApplyFriction`（`0x142de2010`）阶段计算地面滑行衰减时**不乘 `1.225f`**，因此停步后的每拍衰减比例依然是 **`0.6 × 0.91 = 0.546`**，而非像冰面那样变滑；空中加速度（`0.02` b/t²）亦不受灵魂沙影响。

## 6. 与现行参考资料差异澄清

1. **创造模式并非无条件免疫蜘蛛网/细雪/浆果丛**：站在地面的创造玩家同样触发 `(0.25, 0.05)` 等减速；必须**双开 `Flying` + `Instabuild`（实际起飞）**才免疫。
2. **甜浆果丛 `growth = 0`（无浆果幼苗）已经具备完整减速与免摔**：仅刺伤判定要求 `growth > 0`。
3. **灵魂沙并非修改阻尼系数**：地面滑行阻尼仍是 `0.546`，只是方块摩擦被 `1.225×` 缩放，导致加速度缩减为 `(1/1.225)^3 ≈ 0.54399×`；同理空中 `0.02` 加速度完全不变。
4. **细雪冰冻仅改 `SharedAttributes::MOVEMENT_SPEED`**：地面最大减半，空中加速度 `0.02` b/t² 完全不变。
5. **穿皮革靴从超过 `2.5` 格落入细雪会穿透下沉**：`PowderSnowBlock::getCollisionShape` 将顶面碰撞降至 `0.9` 触发穿顶下沉，但仍保持 `0` 摔落伤害。
