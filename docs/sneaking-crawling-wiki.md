# 潜行、爬行与姿态尺寸指南（基岩版 `1.26.51.01`）

在基岩版里，「蹲下」不只是把镜头压低：玩家的碰撞箱会真的变矮，**1.8 → 1.49**；
头顶再矮一点就自动切成**爬行**（**0.6**），而且这个切换是**按头顶净空取最低可行档**、
不需要玩家按键。潜行与爬行的移速都是行走的 **0.3 倍**，`迅捷潜行` 每级 **+0.15**；
边缘防跌落的门槛则是 **0.025 格的重叠**——只跟「**有没有按住潜行键**」有关，跟是不是爬行或被矮顶压低无关。

> **文档分工**：本文面向玩法理解、跑酷与红石/建筑尺寸设计，略去反编译地址与组件编号；
> 完整系统注册顺序、反汇编片段与逐 tick 原始数据见 [`notes/sneaking-crawling-12651.md`](notes/sneaking-crawling-12651.md)。
> 上台阶与 Jump Cancel 见 [`stepping-wiki.md`](stepping-wiki.md)，疾跑见 [`sprint-wiki.md`](sprint-wiki.md)。
>
> **单位约定**：速度单位是 **格/tick**（`1 秒 = 20 tick`），括号内附 **格/秒**；高度均指脚底到目标面。

| --- | --- | --- |

## 二、三档姿态：按净空自动选，不按按键

引擎每 tick 把测试盒在**六个面各内缩 `0.01`** 后依次检查头顶净空，选**能塞下的最矮姿态**：

```text
净空 ≥ 1.79          → 站立（0.6 × 1.8）
1.48 ≤ 净空 < 1.79   → 强制潜行（0.6 × 1.49），sneaking 自动为 true
0.59 ≤ 净空 < 1.48   → 强制爬行（0.6 × 0.6）
净空 < 0.59          → 塞不下，被推出或无法进入
```

实测精细边界（全部由方块碰撞箱回读实际净空）：

| 净空 | `2.000` | `1.9375` | **`1.8175`**（活板门） | **`1.750`**（3 层雪） | **`1.500`**（半砖） | **`1.4375`**（切石机） | **`0.625`**（阳光探测器） | **`0.5625`**（营火） | `0.500` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 姿态 | 站 | 站 | **站** | **蹲** | **蹲** | **爬** | **爬** | **进不去** | **进不去** |
| 高度 | `1.8` | `1.8` | **`1.8`** | **`1.49`** | **`1.49`** | **`0.6`** | **`0.6`** | 被推出 | 被推出 |

几个直接可用的结论：

- **想站着过，实际净空门槛是 `1.79`**（因 `0.01` 内缩，`1.8175` 仍能站立，`1.75` 就已经要蹲了）。
- **1.5 格高的缝隙只能蹲着过**（`1.50 ≥ 1.48` 刚好塞下），而切石机上的 2 格差（`1.4375 < 1.48`）就已经切进爬行。
- **爬行的净空门槛是 `0.59`**：阳光探测器顶留 `0.625` 能爬，营火留 `0.5625` 与半砖留 `0.5` 都塞不下。
- **强制潜行和手动潜行姿态、移速相同，但防跌落不同**：低顶强制潜行时若没有按住潜行键，引擎读到的潜行按键输入仍是 `0`，走到边缘会**直接掉下去**；按住潜行键（height 仍为 `1.49`）才会停在 `247.266`；在矮顶下松开潜行键会继续维持 `1.49` 潜行，走到空旷处后自动恢复 `1.8` 站立（`r03-048` 实测确认）。

### 为什么「蹲着钻进 1 格洞」做不到，该怎么进？

实测：站立（`1.8`）和潜行（`1.49`）走向 `1.0` 格高的通道，都会**卡在洞口**（停在洞口前沿外 `0.3` 处），高度保持不变；原因很直白——姿态按**当前所在空间的净空**拟合，走向洞口时身体还在外侧 `1.8` 空间里。

原版实测有效的进爬行手段（`r03-048`）：

- **活板门压头**：站立玩家头顶一格（`y = feet + 1`）放平并关闭活板门，当拍立刻从 `1.8` 切到 `0.6` 爬行（零过渡延迟）。
- **游泳直接游出水面**：Open-sky 露天水池里游泳（`0.6`，`sneaking = false`）直接向前游过敞开的栅栏门进入 `1.0` 格干通道，离水瞬间维持 `0.6` 爬行状态不弹起。

## 三、潜行与爬行的速度与机动

| 状态 | 速度（格/tick） | 相对行走 | 格/秒 |
| --- | --- | --- | --- |
| 行走 | `0.2159` | `1.00` | `4.32` |
| 潜行（手动 / 强制 `1.5` 净空） | `0.0648` | `0.30` | `1.30` |
| 爬行 / 爬行+潜行 / 爬行+疾跑 | `0.0648` | `0.30` | `1.30`（疾跑不生效） |
| 潜行 + 迅捷潜行 I / II / III | `0.0971 / 0.1295 / 0.1619` | `0.45 / 0.60 / 0.75` | `1.94 / 2.59 / 3.24` |
| 爬行 + 迅捷潜行 I / II / III | `0.0971 / 0.1295 / 0.1619` | `0.45 / 0.60 / 0.75` | `1.94 / 2.59 / 3.24` |
| 强制潜行 + 迅捷潜行 III | `0.1619` | `0.75` | `3.24` |

要点：

- 公式就是 **`0.3 + 0.15 × 等级`**，三级封顶 `0.75`（内部还有 `min(…, 1.0)` 的兜底）。
- **第一拍就生效**：从静止按下前进+潜行/爬行的第一个位移拍，水平位移就是行走的 `0.30`（实测 `0.098 → 0.0294`），没有 1 tick 延迟；空中也共享同一个乘数——按 `a = v' − 0.91·v` 扣掉空气阻力后，空中行走/潜行/SS I/II/III 的加速度精确是 `1.00 / 0.30 / 0.45 / 0.60 / 0.75 ×`（基准 `0.0196`）。
- **迅捷潜行的"额外"部分有 2 拍同 tick 调度滞后**：如果潜行键和前进键**同一拍**按下，**前两拍**仍按 `0.30` 算（输入缩放最先执行，倍率计算在其后，潜行状态位写入更靠后，导致第 1、第 2 拍都读到旧的 `0.30`），第 3 拍起才升到 `0.45/0.60/0.75`；**先按住潜行再走**（或爬行/强制潜行已处于潜行态）第 1 拍就是 `0.45/0.60/0.75`。实测同拍 SS3 首拍 `0.0294`、先按住 SS3 首拍 `0.0735`；这不是装备同步延迟，稳态一定到位。
- **迅捷潜行对爬行和强制潜行完全同样有效**——想做「爬行矿道」，护腿附魔是实打实的收益。
- **爬行不能疾跑**：疾跑键按下 44 tick，疾跑状态位一次都没进，速度一点不涨。
- **爬行可以跳**：1.0 格通道里点跳，脚从 `-40.0` 升到 `-39.6`（`+0.4`）后被头顶挡住，三拍后落回。
- **爬行也能自动上台阶**：只要台阶上方净空仍 `≥ 0.59`，在 `1.0` 格高通道内爬行可以直接走上 **`0.375` 格**高的阳光探测器（`gap_above_step = 0.625`，全程保持 `0.6`）。

## 四、潜行的边缘防跌落：0.025 的重叠

潜行走到方块边缘会停住，这是最常被拿来「贴边」的机制。实测（台面外沿 `z = 247`，玩家半宽 `0.3`）：

| 状态 | 停点中心 | AABB 前沿 | 与台面剩余重叠 |
| --- | --- | --- | --- |
| 站立走 | 直接掉下去 | — | — |
| **手动潜行（按键）** | **`247.274`** | `247.574` | **`0.026`（≥ 0.025）** |
| 低顶强制潜行（**不按键**） | 直接掉下去 | — | — |
| **低顶强制潜行 + 按键** | **`247.266`** | `247.566` | **`0.034`（≥ 0.025）** |
| 爬行（不按潜行） | 直接掉下去 | — | — |
| **爬行 + 按住潜行** | **`247.266`** | `247.566` | **`0.034`（≥ 0.025）** |

怎么读这张表：

1. **判定用的不是你的脚，而是「AABB 向内缩 0.025 后的盒子」还有没有地面。**
   所以你可以把大半个身子探出去：中心越过边缘 `0.266~0.274`，前沿越过 `0.566~0.574`，
   只要还有至少 `0.025` 的箱体压在方块上就不会掉（离散 `0.05` 回退步长使其落在 `[0.025, 0.05)`）。
2. **门控看的是「有没有按住潜行键」，不是姿态或 `sneaking` 状态。** 不按潜行键时，无论是站立、爬行还是低顶强制潜行（`1.49`、`sneaking = true`）都会直接掉下去；**只要按住潜行键**，爬行与强制潜行都能停在边上。
3. **判定向下探的深度是 `1.01 × 最大步高`（默认 `0.568125`）**：实测下方放半砖（`0.5` 落差）或营火（`0.5625` 落差）时不会被当成悬崖、会正常走下去站到下层；放阳光探测器（`0.625` 落差）或空一格（`1.0` 落差）时就会被防跌落拦停在台沿（`z = 247.274`）。
4. **斜着贴台角也拦得住**：45° 斜向按住潜行冲一个方块台角，两个水平轴会**同时**按 `0.05` 的量子往回退（每轮 `dx`、`dz` 各减 `0.05`），最后停在与单轴贴边完全相同的位置——中心越过边沿约 `0.27`（前沿越过约 `0.57`、箱体仍压住 `0.025` 以上）。实测斜向停点 `(208.271, 258.275)`（方块角在 `(208, 258)`），单轴对照 `208.273 / 258.273`，三者一致；不按潜行键斜着走就正常掉下去。注意这 `0.05` 是**回退步长**，不是判定阈值：判定阈值仍是 `0.025` 的重叠。

## 五、和 Java 版的差异

| 维度 | Java `1.21.4+ / 26.2` | 基岩 `1.26.51.01` |
| --- | --- | --- |
| 潜行高度 | `1.5` | **`1.49`**（1.5 的缝只能蹲着过） |
| 低顶姿态 | `Player#updatePlayerPose()` 同样按净空在 `STANDING 1.8 → CROUCHING 1.5 → SWIMMING 0.6` 间降级 | 同思路，三档自动拟合，但碰撞测试盒内缩 **`0.01`**（Java 只内缩 `1.0E-7`） |
| 碰撞测试盒 | 六面内缩 `1.0E-7` | **六面各内缩 `0.01f`** ⇒ 实际门槛 `1.79 / 1.48 / 0.59` |
| 潜行移速 | `0.3 ×` | 同（实测 `0.299993`） |
| 迅捷潜行 | `0.3 + 0.15 × 等级` | 同，且**对爬行与强制潜行生效** |
| 爬行疾跑 / 跳跃 | 不能跑 / 能跳 | 不能跑 / 能跳（被净空裁剪），且可自动上台阶（`gap ≥ 0.59`） |
| 边缘防跌落 | `maybeBackOffFromEdge()` 的 `0.05` 是**回退步长**，不做水平 AABB 内缩；判定看 `isStayingOnGroundSurface()`（Shift 键） | 除 `0.05` 回退量子外，**还在水平四边各内缩 `0.025`**，因此保留约 `0.025` 的重叠余量 |
| 爬行 / 强制潜行防跌落 | 按住 Shift **同样防跌落**（不按照掉） | 同：玩家只看潜行按键，强制潜行不按键也会掉 |

> Java 侧以 `1.21.4+ / 26.2` 的 `updatePlayerPose()` 与 `maybeBackOffFromEdge()` 为机制对照，未在本机复测。

## 六、能直接拿去用的几条

1. **矿道净空按 1.79 以上设计才站得直**（实测活板门下 `1.8175` 可站立）；`1.5` 的缝是「蹲着过」，不是「站着过」。
2. **`0.59 ~ 1.48` 就是爬行道**（`0.625` 阳光探测器底缝能爬，`0.5625` 营火与 `0.5` 半砖进不去）。
3. **爬行不需要按键**，但蹲着挤不进 1 格洞，要靠活板门压头、游泳游出水面或下落。
4. **爬行矿道配迅捷潜行 III 等于 `0.75 ×` 行走**（`3.24` 格/s），比无附魔快一倍半；头顶留足 `≥ 0.59` 时还能直接走上半格台阶。
5. **想靠「强制潜行」不按潜行键安全贴边会翻车**——低顶不会自动帮你防跌落；无论站、蹲还是爬行，贴边都要**按住潜行键**。
6. **低处落差 `≤ 0.5625`（半砖 / 营火）不算悬崖**，潜行走到边缘会直接走下去；要 `≥ 0.625` 的落差才会在边缘刹住。
