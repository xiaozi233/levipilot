# 基岩版有 16 格/tick 的速度上限吗？（1.26.51.01 实测 + 逆向）

社区 Wiki 的旧 `README.md` 里一直留着一句待核实的传闻：**“A player have 16 b/t absolute speed cap.”**（玩家有 16 格/tick 的绝对速度上限）。现在可以给出确定答案：**存在。** 基岩版在碰撞解算入口对“本 tick 的移动请求”做了一次**三维模长 ≤ 16** 的等比缩限；触发后方向不变、整体缩到 16 格/tick。常规玩法几乎摸不到它，但只要把移动速度叠到足够高（例如灵魂疾行 + 满级迅捷），就能实测到它精确停在 16。

> **文档分工**：本文面向玩法理解与跑酷实战，略去反编译地址；完整函数定位、常量地址、组件布局与逐 tick 原始数据见 [`notes/speed-limit-12651.md`](notes/speed-limit-12651.md)。
>
> **单位约定**：速度单位默认 **格/tick**（`1 秒 = 20 tick`），括号内附格/秒。

---

## 一、一分钟结论

| 问题 | 答案 |
| --- | --- |
| 有没有 16 b/t 的上限？ | **有**：每 tick 的移动请求 `MoveRequest.mSpeed` 三维模长 ≤ 16（`320` 格/s） |
| 是分轴各 16 吗？ | **不是**：球形范数。45° 斜向时单轴各约 `11.3137`，模长才是 16 |
| 截断的是什么？ | 碰撞解算的**输入速度**；不是位置、不是 `getVelocity()` 的读数 |
| 什么时候触发？ | 本 tick 请求速度超过 16 时；`≤16` 完全不动 |
| 普通疾跑会撞到吗？ | 不会。疾跑 `0.281`、迅捷 255 疾跑 `14.65`，都在 16 以下 |
| 蓝冰能撞到吗？ | **不能**。蓝冰滑度越高，加速度越小（按 `(0.6/滑度)³` 缩放），稳态只有 `11.42` / `14.85` |
| 怎么才能撞到？ | 灵魂疾行 III + 迅捷 255 + 疾跑：实测连续多 tick 精确停在 `15.9998 ~ 16.0` |
| 撞顶后动量会保留吗？ | **会（无碰撞时）**。`16` 只截断当拍位移，不改写内部动量 `mPosDelta`（仍可攒过 `16`） |
| 传送算不算超速？ | 不算。`/tp` 直接设位置，不经过移动请求，和这个上限无关 |

## 二、这个上限具体在哪、怎么作用

### 1. 位置：碰撞解算的入口

玩家的移动管线大致是：

```
输入/疾跑 → 摩擦/流体/攀爬 → 写出本 tick 的移动请求（MoveRequest.mSpeed）
        → 抓取碰撞箱（此处做 16 b/t 模长缩限）
        → 碰撞解算 → 写回位置/状态 → 收尾
```

缩限发生在**抓取碰撞箱之前**：先看请求速度的平方和，超过 `16² = 256` 就把三个分量归一化再乘 16。所以无论前面叠了多少加速（迅捷、灵魂疾行、流体、击退），进入碰撞解算时最多就是 16。

### 2. 形式：球形，不是立方体

- 单轴直线：`|v|` 到 16 就停。
- 45° 斜向：两个水平轴各 `16/√2 ≈ 11.3137`，合起来仍是 16。
- 斜向下坠同时高速前进：同样按三维长度缩放，不会出现“水平 16、垂直再 3.6”的立方体边界。

### 3. 截断只拦“当拍位移”，不消掉“内部动量”

`16 b/t` 缩限只修改传给碰撞解算的 `MoveRequest`，不会回写清空无碰撞轴上的 `StateVector::mPosDelta`。因此当你在没有撞墙的跑道上把加速堆过 `16` 时，每 tick **真实走出的步长被压死在 16**，但内部动量还在按未截断的公式继续往上攒（例如地面摩擦 `0.546` 后，实测 `mPosDelta` 仍能涨到 `9.07`、`10.81`，明显高于 `16 × 0.546 = 8.736`；跑出平台腾空后的第一拍位移也会释放出超过 `8.736` 的 `9.09`）。只有在碰到实体墙面、或垂直落回地面清零对应轴时，对应轴动量才会被重置。

## 三、为什么平时跑不出来

| 场景 | 稳态速度（格/tick） | 格/秒 | 会撞 16 吗 |
| --- | --- | --- | --- |
| 走路 | `0.2159` | `4.32` | 否 |
| 疾跑 | `0.2806` | `5.61` | 否 |
| 迅捷 255 走路 | `11.27` | `225` | 否 |
| 迅捷 255 疾跑 | `14.65` | `293` | 否（差一点） |
| **蓝冰** + 迅捷 255 走路 | `11.42` | `228` | 否 |
| **蓝冰** + 迅捷 255 疾跑 | `14.85` | `297` | 否 |
| **灵魂疾行 III + 迅捷 255 疾跑** | 目标 `21.4+` | — | **是，封顶 16** |
| 创造飞行 / 疾跑飞行 | `0.512` / `1.085` | `10` / `22` | 否 |
| 自由落体终速 | `-3.92` | `-78` | 否 |
| TNT 2.5 格爆炸 | 峰值 `0.70` | `14` | 否 |

两个反直觉点：

1. **满级迅捷本身就到不了 16**：255 级疾跑稳态 `14.65`，离 16 只差一点，这大概就是“16 上限”传闻的由来。
2. **蓝冰不是加速神器**：滑度 `0.989` 让摩擦变小，但基岩版的加速度也按 `(0.6/滑度)³` 一起变小（约为普通地面的 `22%`），两者叠加后反而比普通地面略低。实测蓝冰首 tick 只有 `1.142`（普通地面同条件约 `5.1`）。

## 四、怎么在游戏里亲眼看到 16

1. 铺一条 **灵魂沙** 跑道（灵魂土也可以）。
2. 穿一双附魔 **灵魂疾行 III** 的靴子。
3. 喝 **迅捷 255**（命令：`/effect @s speed 400 255 true`）。
4. 疾跑直行，逐 tick 记录位移：你会看到速度 `10.7 → 16.0 → 16.0 …` 连续几 tick 精确停住。
5. 改成 45° 斜向（前进 + 平移）再跑一次：两个水平轴会各停在 `11.31` 左右，合起来仍是 16。

这正是 `1.26.51.01` 的实测结果（逐 tick 原始数据见技术文档）。

## 六、对跑酷/速通的实用结论

1. **速度叠到 16 就是硬顶**：迅捷、灵魂疾行、冰面、流体等任何组合都不会让单 tick 位移超过 16；想更快只能靠“换位置”（传送）而不是“提速”。
2. **满级迅捷疾跑 = 14.65**，离上限只有一步；再叠灵魂疾行会立刻撞顶，边际收益为零。
3. **蓝冰适合保持速度、不适合加速**：它的加速度只有普通地面的约 22%，短距离内反而更慢；长距离稳态也略低于普通地面。
4. **撞顶后其实可以“攒内部动量”**：无碰撞时 `mPosDelta` 不被 `16` 截断；虽然每 tick 实际位移还是过不了 16，但一旦松开按键减到 16 以下或冲出平台起飞，后续几拍滑行距离仍会按之前攒高的动量释放。
5. **联机回拉与这个上限无关**：服务端另有一套 4 格位置接受窗口，管的是位置一致性，不是速度。
