# 基岩版疾跑机制完全指南：起跑、断疾跑、`f65` 闪烁与疾跑跳（`1.26.51.01`）

在《我的世界》基岩版（MCBE）中，疾跑是一套看似简单、实则处处藏着硬判定规则的系统：**它只承认正前方 ±45° 的输入扇区，切到倒车或纯侧走会立刻熄火；撞墙后不断疾跑取决于一个 `5e-5` 格的主轴位移差，而就在临界角附近（`f65`），会出现每 tick 闪断一次的奇特现象；但在起步延迟与疾跑跳上，它又在地面和空中实现了完全零延迟、只认状态位的 `+0.2` 水平加速。**

> **文档分工**：本文面向玩法理解、跑酷线路设计与 Java/Bedrock 机制对照，略去底层反编译地址与内部组件编号；完整四系统入口、`5e-5` 汇编判定、组件绑定与逐 tick 实测原始数据请参阅 [`notes/sprint-12651.md`](notes/sprint-12651.md)，正弦表“半角”详情联动 [`angles-wiki.md`](angles-wiki.md)。

> **单位约定**：文中速度单位默认是 **格/tick**（$1\text{ 秒} = 20\text{ tick}$），括号内附 **格/秒**；偏航角 `0°` 对准 `+Z` 墙面法线，`90°` 对准 `+X` 墙面法线。

## 三、起跑、保持与取消规则

### 1. 前向 `±45°` 扇区与饥饿门槛

疾跑系统每拍先读取移动输入向量 `(横移 x, 前进 y)` 与允许状态位，只有**全部满足**下面条件才允许开启或维持前向判定：

- **向前分量** $y > 0$，且输入向量总长度 $\sqrt{x^2 + y^2} \ge 0.707107$（即 $\frac{\sqrt{2}}{2}$）；
- **横移幅度** $|x| \le 0.707107$（把有效摇杆/按键方向锁定在正前方左右各 `45°` 内）；
- **状态与饥饿限制**：食物等级高于 **`6`**（食物格 `≤ 3` 只鸡腿时不可疾跑；骑乘时改看坐骑是否允许疾跑），同时不能处于**失明**或**使用物品减速**（如吃东西、拉弓）状态；
- **游泳与水中起跳规则**：处于**游泳姿态**时跳过撞墙与前向输入取消判定，只在离开水面时结束；但若在**非游泳姿态**下身处水中且按了跳跃，会立刻取消疾跑。

### 2. 双击前进（`7` tick 窗口）与独立疾跑键

- **独立疾跑键（Sprint Key）**：只要满足上方起跑门控，按住或触发疾跑键**无论在地面还是半空中都能直接起跑**；
- **双击前进（Double-Tap `W`）**：首次满足前向扇区时写入固定 **`7` tick** 倒计时（每拍减 `1`），窗口耗尽前重新触发前向扇区即可起跑，但游戏明确要求玩家此时**处于地面、水中或飞行状态**——因此在纯半空中双击 `W` 无法启动疾跑。

**实机确认**（`0.01°` 同轮录制）：地面两次 `W` 键沿间隔 `1~2` tick 能起跑、`5~9` tick 不起跑；**起跳离地后双击 `W` 三档全不起跑**，而空中按独立疾跑键立刻起跑。

`gap=5` 失败要说清楚：**窗口本身仍是 `7` tick**，不是窗口变小了。程序侧"按住 1 tick + 间隔 5 tick"合计 6 tick，再叠加 HID 键沿排队延迟就跨过了从**第一次按下**起算的 `7` tick `mSprintTriggerTime` 倒计时；`gap=1/2` 的合计延迟落在窗口内所以能起跑。另注意倒计时按 tick 计数而非"是否落地"：如果落地时窗口还没耗尽，落地那一拍会合法起跑——别把这误认成"空中能双击"。

对应到键盘操作，实测起跑与切换保持矩阵如下：

| 输入组合 | 静止起跑 | 疾跑中切换（按住疾跑键） |
| --- | --- | --- |
| **只按前进（`W`）** | ✅ 第 1 个状态拍立即置位 | 保持 |
| **前进 + 侧移（`W + A/D`）** | ✅（仍在 `45°` 扇区内） | 保持 |
| **纯侧移（`A` 或 `D`）** | ❌ 全程无法起跑 | **切换拍立刻断** |
| **只按倒车（`S`）** | ❌ 全程无法起跑 | **切换拍立刻断** |
| **倒车 + 侧移（`S + A/D`）** | ❌ 全程无法起跑 | **切换拍立刻断** |
| **前进 + 潜行** | — | **切换拍立刻断** |
| **前进 + 跳跃** | — | 保持（空中依然算疾跑） |

### 3. 起跑禁令的实机确认（失明 / 使用物品 / 水中 / 饥饿）

## 四、撞墙断疾跑与 `f65` 高频闪烁原理

旧版社区 Wiki 曾猜测“上一拍哪一轴速度大，撞墙后只要那一轴位移小于 `5e-5` 就断，且在 `f65` 附近会闪烁”。通过静态反汇编与扩宽跑道实测，**这个公式得到精确证实，而且物理机制可以算到小数点后两位。**

### 1. 游戏内部怎么判定“撞墙断不断”？

只要你仍满足前向 `±45°` 扇区且处于疾跑状态，每拍判定遵循非常简单的两步：

1. **先选“主轴”**：看上一拍记录的水平待执行位移（动量），比较 $|Z_{\text{上}}|$ 和 $|X_{\text{上}}|$ 谁更大；
2. **再查“占优轴这拍有没有走动”**：如果占优轴这一拍的实际位置变化量 $|\text{当前坐标} - \text{上拍坐标}| < 0.00005$（即 **`5e-5` 格**），就立刻触发停跑，取消疾跑状态。

因此结果只有三种情况：

- **被墙挡死的一轴占优**：这一轴被墙顶住几乎走不动（变化量 `< 5e-5`），判定成立 → **断疾跑**。
- **沿墙滑动的一轴占优**：玩家正在沿着墙往前擦，滑动轴每拍位移远大于 `5e-5` → **不断疾跑**。
- **两轴分量刚好打平**：这才是 `f65` 闪烁的真正秘密。

### 2. 为什么临界角正好是 `24.42°`（距墙 `65.58°`），而且会“每拍一闪”？

假设你斜着擦一面沿 `X` 方向延伸的 **Z 墙**（正撞是 `0°`），地面阻力是 `0.546`：

- 被墙挡死的 `Z` 轴每拍速度清零，上一拍留下的待推量只有当拍新产生的推墙输入分量，正比于 $\cos\theta$；
- 沿墙自由滑动的 `X` 轴能够一路吃满地面惯性加速到稳态，上一拍留下的滑动动量是稳态位移的 `0.546` 倍，即 $\frac{0.546}{1 - 0.546}\sin\theta$。

令两个分量相等（$|X_{\text{上}}| = |Z_{\text{上}}|$），约掉共同常数项立刻得到临界方程：

$$\frac{0.546}{1 - 0.546} \sin\theta = 0.546 \cos\theta \implies \tan\theta = 1 - 0.546 = 0.454 \implies \theta \approx \mathbf{24.42^\circ}$$

换算成“视线与墙面本身的夹角”，就是 $90^\circ - 24.42^\circ = \mathbf{65.58^\circ}$——**这就是跑酷圈常说的 `f65`！**

而紧挨在临界角下方那条极窄的夹角带（实测 **`23.5° ~ 24.42°`**），之所以会出现 **`1 → 0 → 1 → 0` 的逐拍高频闪烁**，是因为“疾跑加速”和“疾跑断档后的残余惯性”正好在这里咬合：

```text
第 N 拍（疾跑态）：推墙新分量按 1.3× 算，Z 略大于 X ──▶ 触发“Z 被挡死”，立刻断疾跑！
                                                          │
                                                          ▼
第 N+1 拍（走路态）：推墙力突然缩回 1.0×，但沿墙 X 轴还带着上拍疾跑余温！
                     此时 |X_上| > |Z_上|（滑动轴反超）──▶ 重新满足前向起跑条件，立刻恢复疾跑！
                                                          │
                                                          ▼
第 N+2 拍（恢复疾跑）：推墙力又涨回 1.3×，|Z_上| 再次反超 ──▶ 再次断疾跑……（无限循环）
```

实测数据直接印证了这个循环：在闪烁带内，角色速度在相邻两拍之间按 **`0.0986 ↔ 0.1065` 格/tick** 规律震荡，状态位每拍切换一次。

### 3. `0.01°` 精细扫描：临界角到底在哪一档？

把两个临界区各拆成 13 档、每档 `0.01°`，逐档录 45 tick（贴墙后必须全程贴地、法向速度 `≤0.02`）。分类只看**触墙且前进/疾跑仍按住**的那段窗口（起步 `0→1` 与末尾松键 `1→0` 不计）：

| 墙 | 触墙后全程保持（稳定滑行） | 触墙后闪断（逐拍翻转） | 精确转折 |
| --- | --- | --- | --- |
| **Z 墙** `24.38° ~ 24.50°` | `24.43° ~ 24.50°`（8 档，22 拍窗口内一次都没掉） | `24.38° ~ 24.42°`（5 档，22 拍窗口内 `11` 拍为 `0`） | **`24.42° ↔ 24.43°`** |
| **X 墙** `65.50° ~ 65.62°` | `65.50° ~ 65.58°`（9 档，27 拍窗口内一次都没掉） | `65.59° ~ 65.62°`（4 档，27 拍窗口内 `13` 拍为 `0`） | **`65.58° ↔ 65.59°`** |

理论 `arctan(1−0.546) = 24.418049°`、补角 `65.581951°` 与两个实测转折带（Z `(24.42°, 24.43°)`、X `(65.58°, 65.59°)`）相差都只有 `0.002°`——不到半个 `0.01°` 档，且两处互为 `90°` 补角。
机制上也不再是猜测：游戏在**这一步移动开始前**把期望位移方向存进 `mLastDelta`、把起点位置存进 `mLastPos`；
碰撞完成后拿"实际净位移"和那个期望主轴比较。临界角附近两者在相邻拍轮流占优，于是状态位一拍一翻。
判据读的是**上一步已完成的移动**（`PlayerPreMove` 在疾跑判定之后、移动/碰撞之前才写快照），所以第一次断位总比贴墙那一拍晚 `1` tick。

| `0°` / `1°` / `5°` / `10°` / `15°` / `20°` | 接触当拍断掉后不再恢复 | **单次断疾跑** |
| **`23.5°` / `24.0°` / `24.3°` / `24.4°`** | **记录内翻转 `24~25` 次** | **逐拍高频闪烁**（速度约 `0.099 ↔ 0.107` 抖动） |
| `24.5°` / `24.7°` / `25°` / `30°` / `45°` / `65°` | 全程保持 `1` | **稳定贴墙滑行** |

| **`65.6°`（`24.4°`）** | **记录内翻转 `29` 次** | **逐拍高频闪烁** |
| `65.58°`（`24.42°`） / `65.5°`（`24.5°`） / `65°`（`25°`） / `45°`（`45°`） | 全程保持 `1` | **稳定贴墙滑行** |

两个墙面的临界点恰好互补：$24.42^\circ + 65.58^\circ = 90^\circ$，完全排除了视角朝向的偏差。

> **贴墙静止起步 vs 跑起来再撞墙**：如果玩家一开始就已经贴死在墙边静止起步（沿墙速度从 `0` 开始爬坡，前几拍滑动惯性还没攒起来），闪烁带会往大角度挪：实测在 **`24.4°`** 起跑后断、24 拍贴墙窗口里再没恢复过（每拍都是"重起又被同拍取消"），**`25°`** 会闪烁 `21` 次，**`45°`** 先闪 `3` 次再稳住，**`65°`** 起步就全程稳定。差别不在按键（两组都按住前进+疾跑），而在起步那几拍滑动轴没有存量：跑入触墙时滑动轴已加速到稳态，相邻两拍的占优轴才会来回翻。

## 五、零延迟起步与疾跑倍率

| 场景 | 首拍水平速度（格/tick） | 格/秒 | 与走路比值 |
| --- | --- | --- | --- |
| **地面走路起步** | `0.0980` | `1.96` | `1.0×` |
| **地面疾跑起步** | **`0.1274`** | **`2.55`** | **`1.30×`** |
| **空中走路首拍** | `0.0196` | `0.39` | `1.0×` |
| **空中疾跑首拍** | **`0.02548`** | **`0.51`** | **`1.30×`** |

- 无论是站在地面从静止起步，还是先跳到半空后再按前进+疾跑，基岩版**都在第 `1` 拍直接吃到完整的 `1.3×` 加速**，没有 Java 1.8 那种“延迟 1 tick”的问题。
- 在同一 tick 的系统调度顺序里，疾跑触发器运行在移动速度和位移计算之前；当拍置上疾跑位并挂上 `0.3` 的 `MULTIPLY_TOTAL` 移速乘数（`0.1 × (1 + 0.3) = 0.13`）后，同一帧内的地面移动（`0.98 × 0.13 = 0.1274`）与空中移动（`0.98 × 0.02 × 1.3 = 0.02548`）立即读到新速度。

## 六、疾跑跳 `+0.2` 格/tick 水平冲量

在疾跑状态下按跳跃离开地面时，游戏会在**起跳这一拍的待执行水平位移**上额外叠加固定 **`0.2` 格/tick** 的水平冲量，并按玩家当前偏航角查 **`65536` 项正弦表**分解到 X/Z 轴：

$$\Delta v_x = -0.2 \cdot \sin_{\text{表}}(\text{yaw}), \qquad \Delta v_z = +0.2 \cdot \cos_{\text{表}}(\text{yaw})$$

正因为这里用的是查表而非标准三角函数，**普通疾跑跳也是基岩版少数几个依然能吃到 `+0.0048%` “小半角”加成的动作之一**（详见 [`angles-wiki.md`](angles-wiki.md)）。

四组针对性实测对照（同一套起跳条件下的水平待执行位移增量）：

| 起跳场景 | 实测额外水平增量（格/tick） | 是否获得 `+0.2` |
| --- | --- | --- |
| **直线走路起跳** | `0`（仅常规摩擦递推 `0.11474`） | ❌ |
| **直线疾跑起跳** | **`+0.20000`**（`0.546 × (0.14578 + 0.1274) + 0.2 = 0.34916` 逐位成立） | ✅ |
| **正撞墙断疾跑后起跳**（`sprint = 0`、速度 `0`） | `0` | ❌ |
| **25° 贴墙滑行时起跳**（`sprint = 1`、沿墙速度仅 `0.11859`） | `(-0.08450, +0.18126) = 0.2 × (\sin 25^\circ, \cos 25^\circ)$，模长 **`0.19999`** | ✅ |

**核心结论**：疾跑跳冲量的开关**只检查当前是否处于疾跑状态位，完全不看你现在的实际速度有多慢**。哪怕靠贴墙把滑行速度压到了比普通走路还慢的 `0.11859` 格/tick，只要角度守在 `≥ 24.5°` 保住了疾跑位，起跳瞬间依然能把这完整的一份 `0.2` 格/tick 冲量打满；一旦角度偏正导致撞墙断疾跑，哪怕同位置起跳也立刻颗粒无收。

## 七、跑酷实战速用清单

1. **斜擦墙面保疾跑**：跑酷擦墙蹭边时，角度务必避开 `≤ 20°` 的正撞区和 `23.5°~24.42°`（距墙 `65.58°~66.5°`）的 **`f65` 闪烁带**，尽量以与墙面法线 **`≥ 25°`**（距墙 `≤ 65°`）的角度擦过，或者靠高角度稳定滑行后再起跳，依然能带出完整 `+0.2` 疾跑跳冲量。
2. **贴墙静止起跳要多偏一点**：如果是贴在墙边从零速度起步并想靠擦墙起跳，需要把视角多转到与墙法线至少 **`45°` 以上**（避开 `25°` 起步闪烁区），才能一两拍内稳定保持疾跑。
3. **倒车 / 纯侧走切按键会秒断**：在窄平台上靠 `A/D` 或 `S` 微调落点会当拍断掉疾跑，想保住疾跑只能用 `W` 配合 `±45°` 内的斜前 `W + A/D` 转向，或者直接扭视角用 `W` 对齐目标。
4. **饥饿与零延迟红利**：确保饥饿值大于 `6`（`3` 格以上鸡腿）；一旦起跳或需要滞空微调，不必再像 Java 1.8 那样担心空中第一拍少加速一帧。
