# 触屏视角、触控布局的摇杆规则与键鼠差异（基岩版 1.26.51.01 通俗版）

本文面向触屏玩家与跑酷研究者，讲清三件事：**触屏拖动视角每 tick 转多少度**、**三种触控布局的移动输入怎么来**、以及**它们与键鼠的差别**。
所有结论来自 `1.26.51.01` 的静态反汇编与键鼠路径的运行期实测；地址、指令与证据等级见证据册
[`notes/touch-input-turn-12651.md`](notes/touch-input-turn-12651.md)。

> **先说硬件边界**：写这份指南的机器**没有触摸屏**。触屏分支的全部数字都来自反汇编推导，没有一条是触屏实测；
> 键鼠路径有运行期 hook 实测。标「未定位」的地方是真的没查到，不是省略。

---

## 一、视角事件是怎么流动的

游戏把所有「转视角」的输入做成一条回调链：

```
输入事件（鼠标移动 / 触屏拖动 / 手柄摇杆）
   → 事件派发器：把事件交给一串已注册的处理回调（每个事件跑两遍）
   → 处理器 A（线性级）：把事件乘一个灵敏度系数，累加起来
   → 处理器 B（非线性级，只在触屏拖动时被用到）：把累加值做 1.2 次幂的「加速」
   → 相机：拿到的是已经换算好的「度数」
```

这条链上有三个关键节点，理解它们就能看懂全部公式：

| 节点 | 做什么 |
| --- | --- |
| **分发器** | 收到 `(dx, dy)` 后，要么把它们**累加**到一个待处理槽（鼠标移动就是这样），要么**直接**把 `(dx, −dy)` 交给相机、完全跳过灵敏度曲线（某些脚本/过场用） |
| **线性级** | 把待处理槽里的值乘 `k = 9600 × (0.15 + 0.6v)³`，累加；最后整体乘 `0.3` |
| **非线性级** | 把线性级的累加值做 `0.4 × \|x\|^1.2 ÷ (n+1)`，`n` 是已经累计的帧数 |

**鼠标像素进来时就已经被除了屏幕宽度**：实测 `dx=200 px`、窗口物理宽 `2560` 时，进入处理器的值是 `0.078125 = 200/2560`，
`dy` 则是 `−0.0390625 = −100/2560`（`dy` 在进链前就被取了负号）。所以后面所有公式里的 `d` 都是「像素 ÷ 屏幕物理宽度」，
与窗口高度、系统缩放无关。**具体是哪条指令做的除法还没找到**（它在这条链上游的事件生产者里）。

## 二、灵敏度 `v` 与键鼠的转角

三端共用一条灵敏度曲线（`S` 是设置里的滑条值，0~1）：

```
v = 0.81 × (1.1 × S)^0.6125
```

**键鼠**每像素转过的角度：

```
Δyaw(度)   = dx × 9600 × (0.15 + 0.6v)³ × 0.3 ÷ W
Δpitch(度) = dy × 9600 × (0.15 + 0.6v)³ × 0.3 ÷ W
```

默认 `S = 0.5` 时约 `0.13°/像素`（`W = 2560`）。横向和纵向**完全一样**（实测比值 `0.999999`）。

代码里另有一个只乘**竖直（俯仰）**分量的 `0.7` 因子，门控是「触屏专用快捷栏」那个开关（`hotbar_only_touch`）。
把存档里的 `ctrl_hotbarOnlyTouch` 改成 `1` 再重启，这台机器上比值**仍是 1.0**——没有触摸设备时这个开关不会生效。
所以 `0.7` 目前只有反汇编证据，没有实机数字。

> 上一份指南把这个 `0.7` 写成了「横向因子」，是按错误的轴序推的；按本轮实测的轴序，它乘的是 `dy`（俯仰）分量。

## 三、触屏拖动视角：每 tick 的转角公式

触屏拖动时，线性级的累加值会再过一遍非线性级，然后才交给相机。把两步合并：

```
A = Σ (d ÷ W) × 9600 × (0.15 + 0.6v)³          ← 线性级累加（d 是本 tick 的拖动像素）
T = sign(A) × 0.4 × |A|^1.2 ÷ (n + 1)            ← 非线性级（n = 已累计帧数）
g = min(3, (n + c) − 上一拍的值)                   ← 逐拍增幅，上限 3 倍
Δ(度) = T × 0.15 × g                              ← 交给相机
```

单拍（`n = 0`）展开后：

```
Δ ≈ 3605 × g × |d ÷ W|^1.2 × (0.15 + 0.6v)^3.6
```

三个要点：

1. **指数 `3.6` 是真实代码结构**：线性级把 `(0.15+0.6v)` 立方，非线性级再整体取 `1.2` 次幂，`3 × 1.2 = 3.6`。
   社区 Wiki 旧式 `dx × (32/93275) × (1.6+6.4v)^3.6` 里的 `^3.6` 就是从这儿来的。
2. **`1.6 + 6.4v` 与 `0.15 + 0.6v` 代数等价**：两者比例恰好 `32/3`（都是 `1:4`），所以对灵敏度 `v` 的相对曲线完全一致，只是 Wiki 把常数因子提进了括号（二进制内实际常量是 `0.15/0.6`，`6.4` 未出现）。
   Wiki 里的线性 `dx` 项也不对——本版对像素增量取的是 `1.2` 次幂，**拖得越快，每像素转得越多**。
3. **`32/93275` 那个分母是屏幕物理宽度**，不是固定分辨率；换窗口宽度，分母就变。
4. **`g` 是 Wiki 没有的新项**：连续拖动时每 tick 的增幅有上限（最多 3 倍），并且 `c` 这个基数来自相机对象的一个字段，来源未定位。

**与键鼠的本质差别**：键鼠走的是纯线性（`dx` 的一次方），触屏拖动在它之上多了一层 `|x|^1.2` 的加速和 `g` 的逐拍增幅。

## 四、三种触控布局的移动输入

### 4.1 移动向量的合成规则（三端共用）

不管哪种布局，最终都压成一条二维向量 `mMove`：`mMove.y` 正 = 前，`mMove.x` 正 = 左。规则只有一条：

> **长度超过 1 才被压回 1；不超过 1 就原样保留。**

- 数字方向键（D-pad、键盘）：分量是整数，非零时长度至少为 1，所以**永远是满速**。
- 模拟摇杆：长度 `≤ 1` 原样保留 ⇒ **摇杆推一半就是半速**；推过头会被压回 1。

合成层**没有任何死区**：从摇杆读到的值不会再被裁剪。但摇杆轴在**变成这个向量之前**（UI 控件把像素拖动换算成向量时）
有没有死区、有没有最大半径、固定摇杆与动态摇杆的中心怎么定、往上拖过顶部会不会锁定疾跑——这些**都还没定位**。
本机没有触摸屏，无法实测。

### 4.2 经典 D-pad（Classic）

四个正交键（上/下/左/右）与四个角键（左上/右上/左下/右下）是**八个独立的开关**，同时按下就逐个相加再归一化：

| 按法 | 合成结果 | 角度 |
| --- | --- | --- |
| 单键 | `(±1, 0)` 或 `(0, ±1)` | 0° / 90° |
| 两正交键 | `(±1, ±1)` → `(±0.7071, ±0.7071)` | 45° |
| **一个正交键 + 一个角键** | `(±1, ±2)` → `(±0.4472, ±0.8944)` | **26.565°** |
| 两个正交键 + 两个角键 | `(±1, ±3)` → `(±0.3162, ±0.9487)` | 18.435° |

也就是说，**离开 8 向集合的唯一办法是让角键和正交键同时点亮**（两个位就够，得到 26.565°）。
角键的命中区域、同一根手指滑进角区时会不会和正交键重叠、多点触控下能不能同时点亮——**未定位**。

### 4.3 十字准星（Crosshair）与触屏（Touch）布局

这两种布局的移动摇杆是**虚拟摇杆**（`joystick_frame` / `joystick_knob` 两张 UI 贴图），把手指拖动的像素差换算成上面的二维向量。
换算公式（死区、半径、中心锚点）**未定位**；设置里的 `ctrl_staticJoystick`（固定摇杆）、`ctrl_joystickVisibility`、
`ctrl_usetouchjoypad` 三个开关只确认存在，作用点没追到。
