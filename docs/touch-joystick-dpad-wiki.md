# 触屏摇杆、经典方向键与鼠标转视角的分母（基岩版 1.26.51.01 通俗版）

本文讲清三件事：**触屏虚拟摇杆把手指拖动变成移动向量的规则**、**经典方向键（D-pad）每个键管哪块地方**、以及
**鼠标转视角时「除以屏幕宽度」和「反转 Y 轴」到底是谁做的**。地址、指令与证据等级见证据册
[`notes/touch-joystick-dpad-12651.md`](notes/touch-joystick-dpad-12651.md)。

> **先说硬件边界**：写这份指南的机器**没有触摸屏，也没有手柄**。摇杆和方向键的全部规则都来自读反汇编，
> 没有一条是触屏实测；只有鼠标部分有运行期实测。标「未定位」的地方是真的没查到，不是省略。
> 触屏**拖动视角**每 tick 转多少度，见上一份指南 [`touch-input-turn-wiki.md`](touch-input-turn-wiki.md)；本文不重复。

## 一、鼠标转视角：除法和那个负号

上一份指南留了一个尾巴：鼠标像素进入处理链时「已经被除了屏幕宽度，而且 `dy` 被取了负」，但不知道是哪条指令。
这次找到了，两件事都在同一个函数里——鼠标这个输入设备每 tick 的处理例程。

```
x = 鼠标横向位移 ÷ 屏幕宽度
y = 鼠标纵向位移 × 反转乘子 ÷ 屏幕宽度
```

- **分母就是窗口客户区的物理像素宽度**。这个函数自己存着一份「屏幕宽/高」，窗口大小变化时更新。
  实测窗口为 `2560×1494` 时，它存的宽度就是 `2560`，和用系统接口量到的客户区完全一致；高度不参与。
- **「反转乘子」只有两个值：`−1` 和 `+1`**。它是键盘鼠标设置里「反转 Y 轴」开关的结果：
  关着是 `−1`（所以平时 `dy` 进来就带负号——往下推鼠标是低头），开着是 `+1`。

实测对照（同一台机器、同一组鼠标位移，只改存档里的一行再重启）：

| `ctrl_invertmouse_mouse` | 乘子 | 进处理链的纵向值（`dy=100`） | 向下推鼠标的结果 |
| --- | --- | --- | --- |
| `0`（默认） | `−1` | `−100/2560 = −0.0390625` | 低头 `+12.99°` |
| `1` | `+1` | `+100/2560 = +0.0390625` | 抬头 `−12.99°` |

横向完全不受影响（两种配置下 `Δyaw` 相同），横向与纵向的「每像素度数」比值也仍是 `1.0`。

**关于设置项**：「反转 Y 轴」在代码里是**同一个选项编号、按输入设备分开存的三个值**——键鼠、手柄、触屏各一份，
存档里就是 `ctrl_invertmouse_mouse` / `ctrl_invertmouse_gamepad` / `ctrl_invertmouse_touch` 三行。
手柄和触屏的那两份各由自己的设备处理例程读取。把选项值填进「输入映射表」的那一步代码没有找到，列为未定位。

顺带确认了一条旧悬案：「触屏专用快捷栏」开关（存档里的 `ctrl_hotbarOnlyTouch`）对应的选项编号没错，
只是没有触摸设备时它不生效——所以上一份指南里「竖直方向乘 `0.7`」在键鼠上永远测不到，现在知道原因了：
那段代码只在「当前输入设备是触屏或手柄」时才会走到。

## 二、触屏虚拟摇杆：从手指到移动向量

摇杆每个 tick 做的事可以写成四行：

```
半径 R    = 摇杆可活动区域 的 宽度 ÷ 3
距离 d    = 手指到摇杆中心的距离
d ≤ 25    → 算作没推（死区）
推力 m    = ( min(d, R) − 25 ) ÷ ( R − 25 )        线性；推到 R 就是满推 1，再往外不变
移动向量  = (手指方向) × m
```

- **死区是固定 25**（触控坐标单位），不是半径的百分比。以一个 306 宽的摇杆区域为例，`R = 102`，
  前 25 个单位不动，`25.5` 处推力约 `0.0065`，`63.5`（一半位置）处是 `0.5`，`102` 处满推。
- **推力曲线是直线**：没有平方、立方之类的加速整形；到半径后封顶，推出去更远也不会更大。
- **自动疾跑的触发圈在半径外 5%**：`d > 1.05 × R`（上例即 `107.1` 以外），而且还要「移动即疾跑」这个
  摇杆开关为开。离开移动状态时游戏会松开疾跑键。
- **斜推不会更快**：输出先按方向归一，再乘 `m`，所以模长最多是 1；后面的合成规则（`>1` 才归一化、
  亚单位慢走）见 [`input-joystick-strafe-wiki.md`](input-joystick-strafe-wiki.md)。

**没查到的**：摇杆中心在「固定摇杆」开/关时分别怎么取（哪一刻把中心写下去）；出了触发圈之后**要停多久**才开始疾跑；
发射前还有一步修正的完整形状。这三项都只有部分线索，列为未定位。

## 三、经典方向键（D-pad）：九宫格

经典 D-pad 不是「一个圆盘按角度分区」，而是摆在它的外框上的 **3×3 九宫格**：

```
┌──────────┬──────────┬──────────┐
│ 左上     │    上    │   右上   │
├──────────┼──────────┼──────────┤
│   左     │  (中心)  │    右    │
├──────────┼──────────┼──────────┤
│ 左下     │    下    │   右下   │
└──────────┴──────────┴──────────┘
```

- **四个角键**（左上/右上/左下/右下）就是四个角的完整格子。
- **四个边键**（上/下/左/右）是中间那一行/列的格子，但**整体朝中心缩进去一点点**——缩进量是格宽的 `1.01/22`
  （约 4.6%；来源是按键贴图的 22 像素尺寸）。外框是一个正方形，大小和位置由几个触控布局设置决定。
- **命中判定是「闭矩形」**：手指坐标落在格子里（含边界）就算命中。

### 一根手指

格子和格子内部互不重叠，所以一根手指在某个格子**里面**时只会按下那一个键。只有两种边缘情况会同时命中两格：

1. 正好停在两个格子**共享的边线**上（闭矩形，边线同属两格）；
2. 相邻两个**边键**因为都朝中心缩进，在「十字交角」处叠出一个约 4.6% × 4.6% 的小方块（四个交角各一个）。

这两种情况下游戏按控件顺序处理：**先处理的键占用这次触控，后处理的键只有「上一拍已经是按下状态」才会继续保持**。
所以从一格滑到另一格、恰好停在共享边线上的那一拍，可能短暂出现两键同按；一旦滑进新格子内部，旧键立刻松开
（方向键没有「滑出区域仍保持按下」的设定）。

### 两根手指

每个键自己记自己那根手指，互不干扰。**一根手指按在角格、另一根按在边格，两个键就同时是按下状态。**
按 [`input-joystick-strafe-wiki.md`](input-joystick-strafe-wiki.md) 的合成规则，「上 + 左上」这种组合会走出 `26.565°`
的斜向。不过要把这句话当结论还差一步：角键对应到「斜向」那几个输入位的注册代码没有找到（代码里这些键名只在
两处栈上字符串里出现），所以「角键 = 斜向位」目前仍是推断。

## 四、这份指南更正了什么

上一份触屏指南里有几处读错了，这次按原始指令逐条改正（细节见证据册的勘误表）：

- 「事件分发器把 16 字节事件原样转发」——那个函数其实是「遍历可见界面」的工具，不是分发器；
  真正的分发在输入管理器里，按方向类型各注册了一个回调。
- 触屏分支里的「每 tick 增幅基数」不是从界面对象上读的字段，而是直接传进来的一个数；
  实测它总在 `0.05 ~ 0.89` 之间、每拍都在变，像是「不足一个单位的时间量」（两 tick 之间的插值系数或帧间隔）；它所属的结构体叫什么还没查到。
- 控制非线性加速段那个开关的名字写错了，它的存档键是「完整键盘游戏」；
  而且非线性加速段本身**不看**这个开关，开关为开时跳过的是另一段（鼠标光标瞄准用的）逻辑。
- 「除以屏幕宽度的指令」「`dy` 取负的来源」两项已闭合，见第一节。
