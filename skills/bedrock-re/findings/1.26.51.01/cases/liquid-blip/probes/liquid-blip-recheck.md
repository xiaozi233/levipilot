# Liquid Blip：独立动态复测与勘误

范围：MCBE 1.26.51.01 / LeviLamina 26.51.7。仅动态实验；不新增反编译、指令解码或全局 ECS 调度结论。复用既有 R-F16 的检测入口与 0.3 写点，用 DR 执行观察点采三组件实参及同线程写点；正常 HID 输入，不写位置/速度组件。所有新增机制判断均为 `[实测 live-only]`。

## 方法与有效性

测试前确认生存、非 flying/mayfly、无原有效果和录制/宏/观察点会话。后台 0.7 秒推进 16 tick，没有聚焦/切屏。只添加抗火、水肺以及指定的悬浮效果。源液池为 y=-48/-47 两层、液面 -46，北墙 z=299 顶至 y=-38；逐格回读及液位原值在 JSON 的 geometry。每轮先在池底 settle，再传到指定起点并等待 4 tick；表中起点是传送请求，正式输入前会有少量下沉。

r24-078 跑 17 个窗口；r24-079 补跑 2 个慢升窗口及 2 个不装 DR 的岩浆对照。W-slow-a 初轮前进位仅保持两拍，后续入口覆盖不足，列为无效墙面阴性；原文与数据全部保留。原因未定位，不把缺采当作机制。两次慢升起点复跑均成功。

执行观察点在回执所列客户端/服务端线程读取 rdx/r8/r9 的 32/40/36 字节；同线程下一个入口前的已知写点用于配对。快照只对当前线程一致，不与另一线程原子同步；存在观察开销。盒由入口实参与既有完整公式按 float32 重建，未直接捕获块查询虚槽。录制按位置并以 QPC/tick 约束配对，不能把相同 tick 标签强行等同。

### Q2：阈值零头与运算顺序

```text
v_move = PositionY_after − MobTravel.mPosBeforeMove.y
dy = float32(float32(float32(Y_before − Y_after) + float32(0.6)) + v_det)
gap = float32(AABB.min_y + dy) − liquid_surface
```

### Q3：两侧

本轮 client/server 地址不同，且各自命中入口与写点。`ecs_component(runtime_id, 459100728, length=36)` 读取服务端；客户端由 `ecs_context(state.context, 459100728)` 取得 address，再 `mem_read(address,36)`。检测入口 r9 的 address 与对应侧组件地址匹配。客户端录制应配客户端实参；服务端 tick 可能落在不同编号，不能拿服务端组件替代。所有身份和原始三组件快照保存在 JSON。
